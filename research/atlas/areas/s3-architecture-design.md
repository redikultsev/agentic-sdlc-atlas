# S3. Architecture & design

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

As of late 2026, the strongest evidence in agent-driven architecture says the same thing from several directions. Agents make architectural decisions implicitly ("vibe architecting"). Prose rules such as AGENTS.md or CLAUDE.md do not reliably stop architectural drift. Only deterministic, executable checks (fitness functions and architecture tests in CI, protected from the agent) hold at repository scale. Industry has moved design review earlier in the process, with agents reviewing specs against a codified set of standards before any code exists. Cloudflare's spec reviewer has reviewed about 600 specs. Abnormal AI generates every design doc company-wide with a self-review subagent. Two things are contested. One is whether agent-written design docs are worth anything: critics say cheap RFCs destroy the costly signal that review relied on. The other is whether agent adoption degrades architecture at all. A causal study of Java repos finds smell counts unchanged, while other studies report bloat and coupling that grow with model capability. In design-to-code, benchmarks consistently show agents reproduce how a design looks better than how it behaves or responds to screen size. Supplying design-system context (Figma Code Connect, Google's DESIGN.md) is the most practical lever with measured gains. ADR generation works when the prompt includes the 3-5 most recent prior ADRs. In practice, ADRs are increasingly used as long-term memory that stops agents re-arguing settled decisions.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Deterministic architecture gates (fitness functions for agent output)** | Encode architectural decisions as executable checks (ArchUnit, import-linter, dependency-cruiser, tsarch, custom graph extractors) run in the agent loop and in CI, with rule files protected from the agent via CODEOWNERS so the optimizer cannot weaken the verifier; ratchet for brownfield. | mixed | GyroCompass / Agents Out of Bounds, ArchUnit: Fitness functions for AI-generated code, tsarch for AI coding agents (ANGULARarchitects), maat fitness functions, Thoughtworks Technology Radar Vol. 34 |
| **Codified-standards spec/design review agent** | Before implementation, an agent evaluates design docs/specs against an organization's machine-readable standards corpus (MUST/SHOULD statements), with severity and an approved-vs-enforced lifecycle. | mixed | Cloudflare Codex spec reviewer, Abnormal AI spec tool (Our Design Docs Write Themselves) |
| **Adversarial / multi-perspective design critic and premortem subagents** | Separate reviewer agents (often a different model, or fixed adversarial personas) attack a design before planning. A controlled study finds 'rewrite mandate' adversarial and cross-model review topologies beat parallel-merge. | weak | LLM Consortium for Software Design Refinement, microsoft/amplifier-bundle-systems-design critic, claude-caliper design-reviewer, agentops pre-mortem skill, Abnormal AI spec tool (Our Design Docs Write Themselves) |
| **Agent-generated ADRs and ADRs as agent memory** | Agents draft ADRs from session context or a problem statement; humans decide. ADR index plus a rule file lets the agent read prior decisions and flag conflicts instead of re-arguing them. | mixed | Context Matters: ADR generation context strategies, DRAFT-ing Architectural Design Decisions, ADRs as long-term memory for an AI coding agent (Andrew Connell), harness-engineering adr-fleet, LLMs detecting ADR violations |
| **Throwaway prototype / spike to answer a design question** | Use cheap agent-built prototypes, sometimes several in parallel, to settle a design question, keep the conclusion and discard the code. Some propose a working spike in place of the design doc. | weak | mattpocock /prototype skill, Build Five to Throw Away (agent-building playbook), 2389-research/test-kitchen, The RFC Glut (Tian Pan) |
| **Design-system context injection for design-to-code** | Give the coding agent production component mappings and tokens (Figma MCP + Code Connect, DESIGN.md) so it reuses real components instead of rebuilding from primitives. | mixed | Figma Code Connect in MCP eval, Google DESIGN.md format, Claude Design (Anthropic Labs) |
| **Prompt-to-UI generation tools** | Hosted tools that generate UI designs and prototypes from prompts, sketches or a codebase-derived design system. | weak | Claude Design (Anthropic Labs), Google Stitch, v0 / Figma Make / Lovable category |
| **Benchmarks for architecture and design-to-code capability** | Benchmarks measuring requirements-to-architecture, architectural knowledge, design-to-code fidelity, responsiveness and end-to-end behavior. | strong | R2ABench, SAKE benchmark, FigmaBench, VISTA benchmark, Figma2Code (ICLR 2026), UICrit |
| **Empirical measurement of architectural impact of agents** | Mining and controlled studies of whether agent use degrades architecture (smells, coupling, drift). | mixed | Mining Architectural Quality Under Agentic AI Adoption, AI-Generated Smells, Architecture Without Architects |

## Open gaps

- No measured evidence that design or spec review agents catch real defects: no precision, recall or downstream incident data in any production report found (Cloudflare and Abnormal give volumes, not accuracy).
- No controlled comparison of throwaway prototype vs. written spec vs. ADR-first for design quality or rework when work is delegated to agents.
- Conflicting empirical results on whether agents degrade architecture (the causal Java study says neutral; the AI-smells study says decay grows with capability); there is no reconciliation or multi-language causal study.
- How to keep humans from rubber-stamping agent-proposed ADRs and batch sign-offs; practitioners admit approving almost everything.
- Little evidence on agents choosing system-level architecture (datastores, service boundaries, infrastructure) for real products, as opposed to diagrams or toy tasks.
- UI design generation quality (beyond reproducing an existing design) lacks independent benchmarks; product claims for Claude Design, Stitch and Figma Make are untested.
- No study of fitness-function gaming by agents (weakening rules, adding ignores) beyond advice to protect rule files.
