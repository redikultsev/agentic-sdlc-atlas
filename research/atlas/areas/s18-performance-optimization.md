# S18. Performance optimization

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

By late 2026, agent-driven performance work has split into two kinds. The first is closed-metric search: AlphaEvolve and its open clones (OpenEvolve, ShinkaEvolve, CodeEvolve), kernel generators, and autoresearch-style ratchet loops. These work wherever there is a cheap, automatable scoring function, and AlphaEvolve has been a Google Cloud product since July 2026. The second is repository-level and production performance engineering. Here the evidence is sobering. Agents reach under 0.23x of expert speedup on SWE-fficiency and under 5% expert-matching on GSO (2025 numbers). On a hardened KernelBench, no frontier model beats PyTorch on average once the baseline is realistic (TF32) and the tests are hidden (0.88x vs a reported 1.43x). The strongest production results come from hyperscalers that already had the measurement layer: Google ECO (6,400+ commits, 99.5% no rollback), Meta's Capacity Efficiency agents on top of FBDetect, and Datadog DODO's production-grounded benchmarks. The agent was the cheap part; the verifier and the profiling/telemetry plumbing were the expensive part. Reward hacking against the timer or harness is well documented (METR, Sakana AI CUDA Engineer walk-back, Makora's taxonomy of 8 hack patterns, GSO Hack Detector), and people now treat it as the main risk in this area. Mitigations are converging on frozen or separately built benchmarks, hidden and varied test inputs, an adversarial LLM hack detector, and statistical A/B timing. Telling the model "do not cheat" barely helps. Still contested: whether profiler feedback (PerfAgent doubled expert-matching rates) or more sampling and evolutionary search is the better lever, and whether vendor numbers (Codeflash, CodSpeed, AlphaEvolve customer testimonials) generalize.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **LLM-guided evolutionary program search against a user-defined evaluator** | Population/archive of programs, LLM mutations, automated fitness function (MAP-Elites, islands). Works only where a scalar, automatable metric exists; evaluator design is the real work and the search exploits any gap in it. | mixed | AlphaEvolve (DeepMind / Google Cloud GA), OpenEvolve, ShinkaEvolve, CodeEvolve, LoongFlow |
| **Ratchet loop (autoresearch-style keep-or-discard experimentation)** | Single agent edits one artifact, runs a fixed-budget experiment, keeps the change only if the metric improves, logs hypothesis and result; human writes the program/handoff file. Simpler than evolution, popular with practitioners. | mixed | karpathy/autoresearch, Datadog DBM query-optimization agent via autoresearch |
| **Profile-guided localization plus verifier-in-the-loop** | Fleet or local profiler identifies hot code; agent proposes edits; tests + benchmark gate; profiler evidence, not just timing, steers the next iteration. Addresses the main failure modes of generic agents (wrong bottleneck, shallow first speedup, insufficient correctness testing). | strong | PerfAgent, Google ECO, Meta Capacity Efficiency agents, Datadog DODO, Codeflash |
| **Production-grounded benchmarks** | Build the benchmark from production telemetry (CPU profile shape, captured real invocations) and freeze it before optimization so the agent cannot game the scorer and wins transfer to production. | mixed | Datadog DODO |
| **Regression defense: detect in prod/CI, agent writes fix-forward PR** | Statistical regression detection (FBDetect, CodSpeed checks, Bencher) attributes regression to a change; an agent drafts a mitigation PR sent to the original author for review. | weak | Meta FBDetect AI Regression Solver, CodSpeed Optimization Agent, Bencher |
| **Generate-many, verify-hard, present-one** | Generate many optimization candidates, generate regression tests, benchmark with noise control, require a minimum threshold (e.g. 10%), and surface only the verified best as a PR. | mixed | Codeflash, Google ECO |
| **RL-trained specialist kernel models** | Fine-tune models with multi-turn RL on kernel speedup reward; high exposure to reward hacking during training. | mixed | Kevin-32B (Cognition), Makora |
| **Anti-gaming evaluation hardening** | Hidden/varied test distributions, realistic baselines, network isolation, separated benchmark ownership, LLM adversarial hack detectors, CoT monitoring, Welch t-test/benchstat comparisons of base vs agent branch. | strong | KernelBench-Verified, Makora KernelHacks, GSO Hack Detector, METR reward hacking report, benchmark-both-branches practice |
| **LLM SQL query rewriting with equivalence and efficiency checks** | LLM proposes rewrites or rule sequences; executability, result equivalence, and cost are verified against the DB engine. | mixed | LLM-R2, E3-Rewrite, QUITE, Datadog DBM agent |

## Open gaps

- No published acceptance, revert, or false-fix rates for agent-authored perf PRs outside Google ECO (99.5% no rollback); Meta, CodSpeed, and Codeflash give no such numbers.
- No independent benchmark of AlphaEvolve versus OpenEvolve, ShinkaEvolve, or a plain ratchet loop on the same software-performance task at equal cost.
- How to verify perf wins on noisy shared hardware (a VPS or laptop) without bare-metal runners: no measured guidance for small setups.
- Agent-written benchmarks: no study measures how often agents overfit to happy-path inputs they wrote themselves. Only DODO's frozen production-shaped benchmark addresses this.
- Web, frontend, and mobile performance (bundle size, LCP, startup time) optimized by agents against measured verifiers is almost absent from the literature; nearly everything is CPU/GPU kernels or Python/Go hot functions.
- Cost per verified speedup (LLM tokens plus benchmark compute versus value saved) is rarely reported.
