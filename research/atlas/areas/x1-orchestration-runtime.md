# X1. Orchestration runtime

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

By late 2026 orchestration of coding agents has converged on one shape: a manager or planner splits the work, fresh-context workers do it, and a separate verifier or judge decides whether to continue. Cursor (planners/workers/judge), Factory Missions (milestones with validation phases), Devin's manager-child setup, Composio Agent Orchestrator, Gas Town and Claude Code agent teams all follow it. Several sources make the same point: flat self-coordinating swarms failed (lock contention, risk-averse agents), and Cursor and Cognition both report that coherence holds best when writes stay single-threaded or file ownership is kept separate. Controlled measurements (Google's 180-configuration study, MAST, the single- vs multi-agent paper) show multi-agent setups help on parallelizable tasks, hurt sequential ones by 39-70%, and amplify errors without a central validator. Durable execution is now a commodity (Temporal, Restate, DBOS, Inngest, Vercel Workflow, Cloudflare, Pydantic AI integrations). Whether the agent loop itself belongs inside a replay engine is still disputed: practitioners report history blowout and nondeterminism problems and keep the engine around the agent, not inside its loop. A vendor critique (Diagrid) argues that framework checkpointing (LangGraph, MS Agent Framework, Strands, ADK) is not durable execution at all. Structured verdicts are spreading (Agent SDK JSON-schema outputs, typed task boundaries, hook exit codes that gate task completion), but nobody has published a measurement against text markers.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Fixed pipeline instead of agent-chosen control flow** | Hard-coded phases (localize, repair, validate) where the LLM does not decide the next step. It is cheaper and often competitive, and it is the conceptual ancestor of workflow-graph engines. | strong | Agentless |
| **Durable execution engine wrapping agent steps** | Each LLM call and tool call is a journaled activity or step. A crash resumes from the last completed step, and HITL waits and timers are built in. | mixed | Inngest durable agents / AgentKit, Vercel Workflow DevKit DurableAgent, Temporal OpenAI Agents SDK integration, Pydantic AI durable execution, Cloudflare Workflows / Agents long-running agents, Restate agent integrations |
| **Durability around the loop, not inside it** | Practitioner counter-pattern: the agent turn is one opaque unit that checkpoints decisions to an external store. Recovery means respawning a fresh process instead of replaying. Policies (budgets, loop detection) live in the spawner. Includes a minimal SQLite step log. | weak | r/LangChain thread: Temporal as runtime for long-running agents, You Don't Need Temporal Yet (150-line event log) |
| **Framework checkpointing (superstep or session persistence)** | Graph frameworks snapshot state per superstep or message. Critics argue this lacks automatic failure detection, auto-resume, leases and dedup, so it is not durable execution. | weak | Diagrid: Still Not Durable (MS Agent Framework & Strands), LangGraph interrupts/checkpointer, Microsoft Agent Framework workflows |
| **Event-reaction loop around PRs and CI** | The orchestrator watches GitHub events and injects CI failures and review comments back into the owning agent session. A human is pinged only for judgment calls. | weak | Composio Agent Orchestrator, GitHub Agent HQ / mission control |
| **Structured verdicts and typed handoffs instead of text markers** | Agents return schema-validated JSON (with re-prompt on mismatch). Hooks exit codes gate task completion. Typed artifacts pass between stages. The orchestrator reads session event logs instead of trusting self-reports. | weak | Claude Agent SDK structured outputs, Claude Code agent teams, Composio Agent Orchestrator, awesome-agent-orchestrators (YYLO, tutti, ORCH) |
| **Task ledger outside context (issue DB as coordination substrate)** | Work items, dependencies and agent identity live in a git-backed or SQL ledger that agents query, so state survives sessions and is shared across agents. | weak | Gas Town + Beads, Claude Code agent teams |

## Open gaps

- No published measurement comparing structured JSON verdicts against free-text completion markers for gating pipeline stages in coding agents.
- No controlled benchmark of orchestration topologies on coding tasks specifically (the Google study uses finance, browsing, planning and tool-use, not SWE).
- Success rates per mission or run are not disclosed by any vendor (Factory, Cursor, Cognition give durations and token counts only).
- No good answer for running coding-agent loops inside replay-based engines without history blowout; the advice is folk wisdom only.
- How a manager detects false completion claims from workers (the Gas Town Mayor and Claude agent teams' early-stopping lead) has no systematic treatment beyond 'read the event logs'.
- Cost per merged PR for parallel-agent setups versus a single agent is unmeasured outside self-reports.
