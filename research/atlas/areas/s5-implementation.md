# S5. Implementation

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

As of late 2026 the implementation layer has two settled ideas and several open fights. Settled idea one: the model alone is the wrong unit to compare. Controlled studies (Arena HarnessTax, the Scaffold Effect paper, Strands' 94k trials) find harness choice moves pass rate by only 0-8 pp but moves tokens per solved task by 5x to 40x, and each harness fails in its own way. Settled idea two: long autonomous runs (Cursor's planner/worker fleets, Anthropic's 16-agent C compiler, Ralph loops) live or die on the verifier and the feedback signal, not on the loop. Contested: whether context files and procedural instructions help at all. ETH found AGENTS.md gives no gain at +20% cost, and TDAD found TDD instructions alone increased regressions. Also contested: whether flagship fleet demos are real, after the FastRender browser was found not to compile, and whether productivity gains exist outside vendor self-reports (METR's RCT showed a 19% slowdown, and its follow-up data is unreliable). Model-per-step routing (cheap executor, frontier planner or advisor) is now standard practice, but its quality evidence is mostly anecdotal.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Harness-model pair as the unit of evaluation** | Treat the scaffold (tools, context loading, retries, stop rules) as a first-class variable; compare by cost per solved/accepted task, idle turns and failure fingerprint, not by pass rate alone. | strong | Arena HarnessTax, The Scaffold Effect in Coding Agents (arXiv 2607.22585), Strands 94,000 trials harness cost, Pi minimal coding agent |
| **Minimal context files / surface information not procedure** | Keep always-loaded instructions minimal and non-inferable; give agents targeted facts (e.g. which tests cover which code) rather than workflow prescriptions; load rules/tools conditionally or lazily. | mixed | Evaluating AGENTS.md (ETH SRI Lab), TDAD: Test-Driven Agentic Development, Factory Deferred Context Engine, Stripe Minions, Context Engineering for Coding Agents (Böckeler, martinfowler.com) |
| **Structured compaction vs. handoff to fresh thread** | For long sessions, either compress history into anchored, sectioned summaries (intent, files, decisions, next steps) or abandon compaction and start a new thread with a curated handoff. | mixed | Factory: Evaluating Context Compression, Amp Handoff (No More Compaction) |
| **Hierarchical planner/worker fleets for long-running work** | Recursive planners create tasks, workers grind in isolation, a judge decides whether to continue; periodic fresh starts fight drift. Flat self-coordination via locks failed. | mixed | Cursor: Scaling long-running autonomous coding, Anthropic: Building a C compiler with parallel Claudes, FastRender critique (HN) |
| **Ralph-style infinite loop with external verifier** | A while-loop re-spawning fresh agent sessions against a task queue; progress depends on an objective function, near-perfect tests, browser verification and telemetry feedback. | weak | Anthropic: Building a C compiler with parallel Claudes, Amplitude: Ralph loop for a week |
| **Model-per-step routing (orchestrator-executor / advisor)** | Frontier model for planning, judgment and review; cheaper models for exploration, summarization and routine edits; or cheap driver with frontier advisor at checkpoints. | mixed | Arize: model and harness routing, Aider architect/editor mode, Amp Oracle subagent, Agent-as-a-Router (arXiv 2606.22902), Cursor: Scaling long-running autonomous coding |
| **Unattended one-shot agents interleaved with deterministic steps** | Agent loop wrapped by deterministic code for git, lint and tests; pre-warmed isolated devboxes; bounded CI rounds (at most two); output is a CI-passing PR for human review. | weak | Stripe Minions, Ramp Inspect, Devin 2025 performance review |
| **Test-driven / test-gated agent workflows** | Tests as executable spec and gate; impact-analysis maps, adversarial test generation, hiding or making tests read-only to stop test tampering. | mixed | TDAD: Test-Driven Agentic Development, TDFlow, ImpossibleBench, GTDD (arXiv 2610.02952) |
| **Empirical mining of agentic PRs** | Large-scale MSR studies of agent-authored PRs on GitHub: what merges, what gets rejected and why. | strong | Where Do AI Coding Agents Fail? (MSR 2026), Why Agentic-PRs Get Rejected (arXiv 2602.04226) |

## Open gaps

- No matched-trial evidence that model-per-step routing keeps quality equal; savings are measured, quality is not.
- No independent audit of fleet-scale long-running outputs (Cursor, Anthropic) beyond forum inspection; no standard definition of 'working' for multi-week runs.
- Artifact or file-state tracking across compaction scores poorly everywhere; no public solution is measured against task completion.
- Context-file studies cover Python issue fixing only; effects on convention adherence, review burden and multi-repo work are unmeasured.
- Productivity of solo developers running many parallel agents is unmeasured; METR's RCT covers single-agent use in 2025 and its follow-up is unreliable.
- Few published negative results from Ralph loops (cost blowups, drift) with numbers; most write-ups are success stories.
- Compaction vs handoff (Factory vs Amp) has never been compared head to head on task outcomes.
