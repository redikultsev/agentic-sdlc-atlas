# S7. Code review

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

By late 2026 AI code review is a crowded commodity market: CodeRabbit, Cursor Bugbot, Greptile, Graphite, Copilot code review, Claude Code Review and Codex review all run as agents with tool access to the repository, not as diff-only prompts. People mostly agree on three things. Precision and developer trust matter more than raw recall, and OpenAI and others say so explicitly. Repo-wide tool access and execution improve both precision and recall. The useful production metric is whether the developer changed code in response, which Cursor calls "resolution rate"; per-comment acceptance and thumbs-up reactions are weaker signals. Several things are still disputed. Vendor benchmarks contradict each other (Greptile ranks itself first, Macroscope ranks itself first). An independent run on Martian's bench found raw frontier models with a simple prompt score as well as the commercial tools. Multi-model panels and majority voting help in some reports (Bugbot v1) but show no measurable gain in others (CodePanel's cross-family tests), and voting can hide a single correct dissent. Independent production studies show modest effects: about 38.7% of comments lead to a code change at Atlassian, and effectiveness varies widely across 16 GitHub Actions. Security-focused review and the attack surface of the review bot itself (the CodeRabbit RCE, prompt injection) are a distinct and fast-moving subarea.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Agentic reviewer with repo tools and execution** | Reviewer is an agent that pulls context on demand (grep, read files, run code or tests), not a single prompt over the diff. Reported to raise both recall and precision. | mixed | OpenAI Codex code review (Scaling code verification), Cursor Bugbot, GitHub Copilot code review agentic architecture, Claude Code Review (multi-agent) |
| **Parallel passes + majority voting + validator filter** | Run N bug-finding passes (randomized diff order or different roles), bucket similar findings, keep findings flagged by several passes, then run a validator model to remove false positives. | mixed | Cursor Bugbot, Argus multi-model panel, k-review, CodePanel |
| **Generate-then-filter orchestrator (no vote counting)** | Cheap role-specialized reviewers report everything with confidence. A stronger orchestrator checks each finding against the actual code and drops contradicted ones. Explicitly rejects majority voting because role-specific findings would be lost. | weak | CodePanel, Claude Code Review (multi-agent), Refute-or-Promote |
| **Adversarial or one-dissent-blocks review** | Reviewers try to refute findings or the change itself. For security paths, one evidence-backed dissent blocks the merge, and verdicts must cite real artifacts (tool outputs, hashes). | weak | Refute-or-Promote, Adversarial Review (structured disagreement), Zeeshan Mahmood one-dissent-blocks guide, agent-review-panel |
| **Reviewer independent from author (fresh context or different model)** | Avoid self-attribution bias: the model that wrote the code, or the same conversation, should not grade it. Use a fresh context and possibly a different model family. | mixed | Self-Attribution Bias (Anthropic/MATS), CodePanel, Augment adversarial code review guide |
| **Outcome-based metric: resolution rate / addressed comments** | Measure whether the author changed code in response to a finding, judged by an LLM at merge time. Used both to compare tools and to hill-climb the reviewer. | strong | Cursor Bugbot, Martian Code Review Bench (online), RovoDev Code Reviewer, Does AI Code Review Lead to Code Changes?, OpenAI Codex code review (Scaling code verification) |
| **Offline golden-set benchmarks with precision/recall/F-beta** | Curated PRs or bug-introducing commits with human-labeled expected findings, scored by an LLM judge. | mixed | GitHub ReviewBench, Martian Code Review Bench, IronBee raw LLM benchmark, SWE-PRBench, CR-Bench-v2, SecPRBench, MacroscopeBench, Greptile benchmarks |
| **Risk-stratified auto-approval** | Classify diffs by risk. Low-risk diffs get LLM review plus deterministic checks and land without a human; high-risk diffs go to humans. | strong | Meta RADAR |
| **Security review agent + SAST hybrid** | Combine deterministic SAST with LLM triage or agentic security review to cut false positives and find logic vulnerabilities. | mixed | anthropics/claude-code-security-review, Snyk Evo / VulnBench 2.0, SecPRBench, CodeRabbit Security |
| **Self-hosted BYO-model review bots** | Open-source PR reviewers that run in CI or on your own server with your own LLM key. | weak | Kodus, vercel-labs/openreview, pr-af (AgentField), Mira, Proval |

## Open gaps

- No controlled public study shows that a reviewer from a different model family catches more bugs in agent-written code than a same-family reviewer in a fresh context. Self-preference research exists, but measurements specific to code review are thin and CodePanel's two tests found no effect.
- No head-to-head measurement of majority voting versus an orchestrator filter versus one-dissent-blocks on the same benchmark.
- Vendor benchmarks contradict each other (Greptile, Macroscope, Tenki, CodeAnt each rank themselves first). No neutral, frequently updated comparison of commercial tools with precision and cost, apart from Martian online and IronBee.
- How review quality degrades when an agent fixes review comments in a loop (review-fix-review), for example when the reviewer and the fixer converge on agreeing with each other.
- Long-term effect of AI review on escaped defects and production incidents, outside Meta's confounded RADAR data.
- Total cost and latency per merged PR for multi-agent review at solo scale, with many parallel agent PRs per day.
- Security of self-hosted review bots that hold write tokens and execute linters on untrusted PRs: no systematic survey beyond the CodeRabbit and Qodo disclosures.
