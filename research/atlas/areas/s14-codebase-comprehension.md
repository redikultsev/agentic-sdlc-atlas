# S14. Codebase comprehension

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

As of late 2026, how an agent learns an existing codebase before acting splits into three camps that disagree. The first is just-in-time agentic exploration: grep and file reads, usually run inside an isolated research subagent or a research-plan-implement pass with intentional compaction, as in HumanLayer, Claude Code Explore and Gemini codebase_investigator. The second is a prebuilt index: semantic, structural or graph-based, as in Augment, Sourcegraph, Serena, CodeGraph-style indexes, LocAgent and RepoGraph. The third is pregenerated wikis or context files: DeepWiki, Google Code Wiki, CodeWiki and AGENTS.md. Evidence has turned against the third camp. Controlled studies (ETH Zurich's AGENTS.md study, a two-agent ablation) find that context files and repo overviews do not measurably raise correctness and cost about 20% more. Maintainers report confident hallucinations in DeepWiki, while rubric benchmarks rank DeepWiki below open-source CodeWiki. Grep versus index is the most contested question. Cursor published a 12.5% QA gain from semantic search in Nov 2025, then quietly removed semantic search in Jul-Aug 2026. Inside one harness, a structural index lifts localization by about 40pp and resolve by 8pp, but against an independent grep agent the gains are not significant. Sourcegraph's own corrected run found its earlier MCP advantage was an artifact of a broken baseline. Process-level benchmarks (ContextBench, SWE-QA, RepoProbe, Theory of Code Space, CodeScaleBench) now measure comprehension separately from task success. Their findings: agents favor recall over precision, often drop context they retrieved, and show an 'edit bias' toward patching before they understand. For legacy and mainframe estates, the consensus is a deterministic static-analysis or dependency graph first, then LLM work on bounded units with traceable claims and explicit gaps. Discovering invariants and ownership has only early, weakly evaluated tools.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Research-then-plan with intentional compaction** | Before editing, a separate read-only pass (often an isolated subagent) maps the relevant files, flows and conventions, then compresses the findings into a short artifact (research doc, evidence packet, structured report) that a human reviews and a fresh context consumes for planning and implementation. | mixed | HumanLayer ACE-FCA / research-plan-implement, No Vibes Allowed talk (Dex Horthy), Gemini CLI codebase_investigator subagent, Claude Code Explore / Plan subagents, Code Researcher (Microsoft Research), Evidence packet for legacy code (Towards AI) |
| **Pregenerated codebase wiki / documentation map** | Generate hierarchical wiki pages, diagrams and source citations for the whole repo ahead of time; humans and agents query them instead of the raw code. | mixed | DeepWiki / Devin Wiki, Google Code Wiki, CodeWiki (FSoft-AI4Code) and CodeWikiBench, MemDocAgent (Remember Your Trace), ProdE AI documentation benchmark, DeepWiki maintainer critiques |
| **Persistent repo context files (AGENTS.md / CLAUDE.md / /init)** | A checked-in file of conventions, structure overview and commands, loaded into every session as standing comprehension. | strong | Evaluating AGENTS.md (ETH Zurich / LogicStar), On the Impact of AGENTS.md Files on Efficiency, Do Context Files Help Coding Agents? (two-agent ablation) |
| **Agentic lexical search (grep/ripgrep, BM25-ranked) as the default retriever** | No standing index; the model iterates search -> read -> refine. Argued to be always fresh, private and simple; ranking of grep hits matters a lot. | mixed | Cursor semantic search post and later removal, Is Your Code Context Good? (Dik Rana), Keyword search is all you need (Amazon, AAAI 2026), Codebase RAG vs grep: BM25 ranking (ITNEXT), Is Grep All You Need? (harness study) |
| **Prebuilt semantic / structural / graph code index exposed as tools** | Embeddings, call/definition graphs, LSP symbol tools or cross-repo code search behind MCP tools, so the agent can ask 'who calls X' or 'where is behavior Y' in one call. | mixed | Code Isn't Memory (structural codebase index ablation), Sourcegraph MCP / CodeScaleBench, Augment Context Engine MCP, Serena MCP, LocAgent, RepoGraph, Aider repo map, Turbopuffer talk: semantic retrieval on Claude Code |
| **Deterministic analysis first, LLM on bounded units (legacy/mainframe)** | Static analysis resolves the dependency graph, copybooks, JCL and platform semantics deterministically; the LLM summarizes and extracts rules only from bounded, complete units, with source-line traceability. | mixed | AWS Transform for mainframe (reverse engineering posts), CTBC Bank multi-agent reverse engineering on AgentCore, IBM Bob Premium Package for Z, Thoughtworks: Claude Code and COBOL modernization reality |
| **Explicit invariant / implicit-contract extraction with confidence and gaps** | Agents state the invariants, business rules and cross-component contracts they infer, mark confidence, record gaps for human decision, and later verify them through tests, assertions or fuzzing. | weak | Reversa reverse documentation framework, AgentModernize (Behavioral Specification Graphs), invariant-analysis Claude Code plugin, Code-Augur (specification inference + fuzz falsification), Theory of Code Space benchmark |
| **Process-level comprehension measurement** | Score what the agent understood or retrieved (gold context recall and precision, checklist-verified QA, belief-state probes), separately from whether the final patch passed. | strong | ContextBench, SWE-QA, CoReQA, SWE-QA-Pro, RepoProbe, Theory of Code Space benchmark, Sourcegraph MCP / CodeScaleBench, CodeWiki (FSoft-AI4Code) and CodeWikiBench |
| **Human comprehension as a gate (comprehension debt)** | Treat the team's lost understanding of agent-written code as a debt, and gate merges on a human who can explain the change. | weak | Comprehension debt (Addy Osmani), Cognitive Debt in the GenAI Era (practitioner voices study), Amazon outage traced to agent advice from stale internal wiki |

## Open gaps

- No controlled measurement of research-plan-implement or intentional compaction against a no-research baseline. The evidence is anecdotes from HumanLayer.
- Ownership discovery (who owns a module, CODEOWNERS, people to ask, blast radius across teams) as a comprehension input to agents: nothing measured or even well-described was found.
- Hidden contracts outside the code (runtime config, infrastructure state such as Terraform addresses, downstream consumers in other repos, production data shape) are reported only in incident write-ups. No benchmark covers them except synthetic Theory of Code Space constraints.
- How fast a codebase map, wiki or index goes stale under many parallel agents committing, and how to detect staleness before an agent trusts it.
- Whether comprehension gains on public benchmarks transfer to private or employer repos that models have never seen in training. SWE-QA-Pro hints at memorization confounds.
- Run-to-run nondeterminism of an agent's model of the repo (AWS reported a 17% swing in rule counts). Nobody reports variance of research outputs for general codebases.
- Whether better retrieval or comprehension translates into fewer post-merge defects. Most studies stop at localization, QA score or benchmark resolve rate.
- Cost accounting for the research phase itself (tokens and wall-clock) relative to the rework it prevents.
