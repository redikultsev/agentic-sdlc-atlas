# X4. Context & knowledge

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

By late 2026 there is real controlled evidence on agent context, and most of it is sobering. Four primary studies of AGENTS.md/CLAUDE.md agree on a few things. Agents follow these files almost mechanically. The files add steps and tokens. They do not measurably raise task success: LLM-generated files slightly hurt, and human-written files give a small, non-significant gain. Repository overviews are useless. Skills show the same pattern. Curated skills help on average but vary widely. Self-generated skills do not help. Matched skills often lower pass rates while multiplying token cost. Co-installed similar skills silently replace each other, and these skills are also a live supply-chain attack surface. On retrieval the field is split. Anthropic says agentic grep/read beat embeddings for Claude Code, while Cursor and Augment report gains from semantic indexes, but only as self-reports. The one independent-ish agent test of code graphs found no significant gain over text search. Memory is the least settled area. Naive per-prompt recall can make agents worse. Memory only pays off when the deciding knowledge is not in the repo, and the coding-specific benchmarks for it (SWE-ContextBench, sde-bench, DreamBench-SWE) all appeared in 2026.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Always-loaded context file (AGENTS.md/CLAUDE.md)** | A static markdown file injected into every session with commands, conventions and rules. Evidence: it is useful for non-standard practices and for knowledge missing from both the training data and the repo. It does not work as an architecture overview. | strong | Evaluating AGENTS.md (ETH Zurich, Gloaguen et al.), On the Impact of AGENTS.md Files on Efficiency (Lulla et al.), Do Context Files Help Coding Agents? Two-Agent Ablation (Khatri), Agent READMEs empirical study, context-file-evidence (Orvii), Vercel: AGENTS.md outperforms skills |
| **Compressed index in the context file plus on-disk docs (pointer, not payload)** | Keep a tiny always-loaded index of where docs live and let the agent read files on demand. This removes the 'should I look it up?' decision that on-demand skills require. | mixed | Vercel: AGENTS.md outperforms skills, Claude Code auto memory (MEMORY.md as index) |
| **On-demand skills with progressive disclosure** | SKILL.md folders loaded by name and description match. The weak points are triggering, conflicts between similar skills, prompt length versus content, and supply-chain safety. | strong | Anthropic Agent Skills (progressive disclosure), SkillsBench, WebDev-Skills-Bench (Signal or Noise?), One Skill Too Many (skill conflicts), SKILL.md anatomy and smells study, How Agent Skills Evolve (84k skills), Snyk ToxicSkills audit |
| **Agentic search (grep/glob/read on demand, no index)** | The agent explores the live working tree with shell tools. There is no index to go stale, and this is the default in Claude Code and Codex. | mixed | Claude Code abandoned RAG for agentic search, PipesHub code graph benchmark (text-search baseline) |
| **Semantic or embedding code index** | Vector or hybrid search over chunked code, offered as a built-in or as an MCP service. | weak | Cursor semantic search, Augment Context Engine MCP |
| **Structural code graph / repo map** | Tree-sitter, LSP or SCIP-derived symbol and call graphs, exposed as a ranked map or as MCP query tools. | weak | Aider repo map, Serena (LSP MCP), PipesHub code graph benchmark, codebase-memory-mcp / Graphify / CodeGraphContext |
| **Cross-session memory for coding agents** | Facts, decisions or experiences from past sessions that are stored and retrieved later. Variants: plain markdown memory files, vector recall, agentic reflection and consolidation (dreaming). | mixed | Hindsight sde-bench, SWE-ContextBench, DreamBench-SWE, Claude Code auto memory / Auto Dream, MemoryArena |
| **In-session context management (masking, compaction, summarization)** | Ways to keep the working context small during long trajectories. Simple observation masking matches LLM summarization at half the cost. | strong | The Complexity Trap (JetBrains Research), Anthropic effective context engineering, Chroma Context Rot, IFScale |
| **External up-to-date library docs** | Fetching version-specific third-party documentation at answer time to counter stale training data. | weak | Context7, Vercel: AGENTS.md outperforms skills, DeepWiki |

## Open gaps

- No independent (non-vendor) agent-loop benchmark comparing grep-only, embedding index, LSP/Serena and code-graph MCP on relationship questions (callers, impact) rather than file localization.
- No study of context-file effects on long multi-step feature work or on rule compliance (for example 'never touch git', privacy rules). All studies score issue resolution, which these files are not designed for.
- No measured guidance on the right size or number of rules for CLAUDE.md beyond indirect evidence (IFScale, Context Rot).
- Cross-session memory staleness in plain-markdown memory folders (Claude auto memory) has no outcome evaluation. Consolidation features are unmeasured.
- No study of how context files interact with compaction (whether rules survive /compact) or with many parallel agents sharing one rule set.
- Supply-chain security of personal skill libraries: how often co-installed or plugin skills silently override private rules in practice.
