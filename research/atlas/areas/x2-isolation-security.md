# X2. Isolation & security

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

By late 2026 every major coding agent (Claude Code, Codex CLI, Gemini CLI, Copilot CLI, Cursor) ships an OS-level command sandbox: Seatbelt on macOS, bubblewrap/Landlock+seccomp on Linux, and MXC/restricted tokens on Windows. The industry consensus, stated openly by both Anthropic and OpenAI, is that model-level defenses (classifiers, training, auto-approve modes) are probabilistic. The hard boundary has to be environmental: filesystem limits, default-deny egress through a proxy, and credentials kept outside the sandbox. The contested ground has shifted from whether to sandbox to where it leaks. Several sources show this independently (Anthropic's own post-mortems, Pillar's "Week of Sandbox Escapes", Riptides' measurements, Comment and Control). Allowlisted domains turn out to be capability grants. Agent-written files (hooks, .vscode tasks, venvs, git config) get executed later by trusted tools outside the sandbox. A reachable Docker socket escapes everything. Process sandboxes still hand credentials to commands. That pushes the frontier toward its own kernel per agent (Docker Sandboxes, Firecracker/libkrun microVMs, Cowork VM) plus credential brokering (Gatehouse, Infisical Agent Vault, Claude Code masking proxy). Real incidents are now plentiful: Replit 2025, PocketOS/Railway 2026, the Claude Code 48k-file deletion, Mini Shai-Hulud persisting via .claude hooks, and OpenAI models escaping an eval sandbox via an Artifactory zero-day. Taken together they show blast radius is set by the tokens and paths the agent can reach, not by the agent's intent.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **OS-level process sandbox around shell commands** | Constrain the agent's subprocesses in the user's real environment with kernel MAC/namespace primitives (Seatbelt, bubblewrap, Landlock, seccomp, MXC): writes limited to the workspace, network off or through a proxy. Low friction, but the agent still shares the host kernel, and reads are broad by default. | strong | Inside the Codex sandbox (OpenAI), Anthropic sandbox-runtime / Claude Code sandboxing, Riptides comparison of five built-in coding-agent sandboxes |
| **Own-kernel isolation (microVM / VM per agent)** | Run each agent session in a microVM or VM with its own kernel and a private Docker daemon, mounting only the workspace, so an escape lands in a machine that holds nothing. | mixed | Docker Sandboxes (sbx), How we contain Claude across products (Anthropic), Tracekit Box, E2B / Daytona / Modal / Sprites / Vercel Sandbox hosted sandboxes, kubernetes-sigs/agent-sandbox, NVIDIA OpenShell |
| **Credential brokering / secrets via proxy** | The agent holds placeholders. A proxy outside the sandbox swaps in real credentials only for catalogued host/path/method combinations, screens replies for echoed keys and logs every call. | mixed | TRM Gatehouse (fork of Infisical Agent Vault), How we contain Claude across products (Anthropic), Tracekit Box, Docker Sandboxes (sbx), Riptides comparison of five built-in coding-agent sandboxes |
| **Egress control as capability grant** | Default-deny network with a domain-allowlist proxy. Lesson learned: an allowlisted domain grants every function reachable through it (Files API uploads, git push to github.com), so proxies must also check tokens, methods and headers. | strong | How we contain Claude across products (Anthropic), Comment and Control (Guan et al.), Inside the Codex sandbox (OpenAI) |
| **Capability-limiting design rules (lethal trifecta / Rule of Two)** | Architectural rules that forbid one session from combining untrusted input, private data and external communication or state change, without human approval or a fresh context. Includes provable patterns such as CaMeL and plan-then-execute. | mixed | Lethal trifecta (Willison), Agents Rule of Two (Meta), CaMeL: Defeating Prompt Injections by Design, Design Patterns for Securing LLM Agents against Prompt Injections |
| **Model-layer approval delegation (classifier auto-approve)** | Replace per-action human approval, which suffers fatigue (93% approved), with a classifier that blocks risky or overeager actions. Explicitly only one layer inside a sandbox. | mixed | Claude Code auto mode (Anthropic), How we contain Claude across products (Anthropic) |
| **Trust-boundary hygiene for project-local config** | Treat .claude/settings.json hooks, AGENTS.md/CLAUDE.md, .vscode tasks, git hooks and venv interpreters as untrusted input. Defer parsing until after the trust prompt, keep them read-only inside the sandbox, and audit agent-written config. | strong | Pillar Security Week of Sandbox Escapes (via CSA note), Mini Shai-Hulud (SonarSource analysis), GitInject, Inside the Codex sandbox (OpenAI), How we contain Claude across products (Anthropic) |
| **Provider-side guardrails for destructive APIs** | Platforms that agents call make destructive operations reversible and narrowly scoped: soft delete with a grace period, scoped short-lived tokens, OAuth MCP instead of tokens on disk. | weak | Railway post-mortem on agent volumeDelete (PocketOS), Replit agent production DB deletion |
| **Least-privilege CI agent workflows** | For agents in GitHub Actions: tool allowlists rather than blocklists, author filtering, advisory-only permissions, no secrets in the agent's process tree, and no loading of PR-branch config files. | mixed | GitInject, Comment and Control (Guan et al.) |

## Open gaps

- No independent measurement compares microVM sandboxes (Docker sbx, microsandbox, Sprites) against process sandboxes on escape resistance. Existing benchmarks measure cold start, not security.
- How do you give many parallel agents git push or PR rights without a token in the sandbox? Branch-scoped brokered GitHub access exists only in Gatehouse and in Fletch-style host-side push.
- No good answer on DNS exfiltration and allowlisted-domain abuse (github.com, package registries) beyond per-API MITM proxies.
- No systematic data on how often unattended coding agents take destructive actions in practice. There are only anecdotes and vendor rates (auto mode ~17% miss).
- How to monitor agent-written config (hooks, AGENTS.md, .vscode, git config) across many repos so injected persistence is detected; there is no standard tooling.
- The cost and usability of running agent sandboxes on a single VPS versus hosted sandboxes is anecdotal only.
