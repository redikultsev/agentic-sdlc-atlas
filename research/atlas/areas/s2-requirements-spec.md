# S2. Requirements & spec

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

As of late 2026, spec-driven development (SDD) is widespread: SpecMine counts about 470k spec files in 73k public repos. It is also openly contested. Thoughtworks put it in Assess and warned it may repeat the "bitter lesson". Kent Beck called whole-spec-up-front a bizarre assumption that you learn nothing while implementing. Hands-on tests (Boeckeler, Punnen) found spec bloat, review fatigue and agent-generated guesses that later get treated as binding constraints. Practitioners are moving away from heavy, phase-gated templates toward lighter loops: a short interview ("grill-me", now a built-in command in Google Antigravity), plan mode, and specs kept in sync with code (OpenSpec, Plumb, Augment Intent). Tessl, the main spec-as-source vendor, has pivoted to skills and "software factory" loops. Research is converging on one finding: agents are bad at noticing that a request is underspecified, but asking targeted questions helps a lot (Ambig-SWE reports up to +74%; Ask-or-Assume reaches 69.4% on underspecified SWE-bench). Several 2026 benchmarks (ReqClarifyBench, SpecBench, Dialogue SWE-Bench) find that better coding models are not better clarifiers, and that a harness on top adds nothing to requirement quality. Turning acceptance criteria into tests is most mature in Kiro: EARS criteria become property-based tests, plus SMT-based checks for ambiguity and inconsistency. Elsewhere it is mostly Gherkin guidance and conventions.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Phase-gated SDD templates (specify -> plan -> tasks -> implement)** | Install command templates and a constitution or rules file in the repo. The agent produces requirements, design and task artifacts in sequence, each one reviewed before code. | mixed | github/spec-kit, Kiro feature specs, BMAD, GSD (get-shit-done), Spec Kit Agents, Factory Droid Spec Mode |
| **Relentless interview / grilling before planning** | The agent asks one question at a time and offers a recommended answer. It explores the code instead of asking what the code can answer, and walks the design tree until no branch is open. Output is a shared understanding or a brief, and often feeds plan mode. | weak | grill-me skill (Matt Pocock and forks), Google Antigravity /grill-me, Addy Osmani spec-driven-development skill, Ask or Assume? multi-agent scaffold |
| **Uncertainty-aware clarification (detect underspecification, then ask)** | Separate detecting what is missing from executing. Ask only when the request is underspecified, under a question budget. Evaluated with simulated users built on SWE-bench variants. | strong | Ambig-SWE, Ask or Assume?, ReqClarifyBench, SpecBench / Buddy, Dialogue SWE-Bench, Eliciting Specifications (Lean) |
| **Acceptance criteria as executable checks** | Write requirements in a constrained form (EARS, Given/When/Then, numbered ACs), then compile them into property-based tests, conformance tests or Gherkin scenarios with traceability back to the requirement. | mixed | Kiro property-based testing, Gherkin guidelines for AI (Automation Panda), TiCoder, whenwords conformance tests |
| **Formal requirement linting before design** | Translate natural-language requirements into logic and use SMT solvers to flag ambiguity, inconsistency, incompleteness and the wrong level of detail. Each finding comes back to the user as a two-option question. | weak | Kiro requirements analysis |
| **Spec-anchored / living specs with drift reconciliation** | Keep spec, tests and code in sync over time. Extract the decisions made during implementation from diffs and agent traces, gate the commit on human approval, and fold the result back into the spec. | weak | Plumb (dbreunig), OpenSpec, Augment Intent, Tessl (former spec-as-source) |
| **Spec quality rubrics** | Score spec, plan and task artifacts against requirements-engineering standards (ISO 29148) so authors can see the gaps before the agent fills them with its own assumptions. | mixed | EPIC framework, SpecMine |

## Open gaps

- No real-user (non-simulated) measurement of whether a grill-me style interview reduces rework or pushback compared with plan mode alone.
- No study of clarification for unattended or asynchronous agents, where the human answers hours later or must batch questions across many parallel agents.
- No measurement of spec decay over months in spec-anchored projects, or of the cost of keeping specs in sync.
- Unclear how to stop agent-generated assumptions (success criteria, constitution articles) from silently gaining authority; only anecdotes exist.
- No benchmark linking acceptance-criteria quality to test validity, i.e. whether AC-derived tests actually catch intent violations.
- No measurements of EARS versus Gherkin versus free-form acceptance criteria for agent consumption.
