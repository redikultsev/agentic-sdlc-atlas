# S11. Maintenance & evolution

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

By late 2026, agent-driven maintenance has settled on a common pattern. Something deterministic finds the work: a feature-flag system, Dependabot/Renovate, a scorecard campaign or a codemod. An agent makes the changes that need judgment. A gate made of CI, coverage, static checks and separate property reviewers decides what a human sees, and the human only merges. The strongest evidence comes from companies writing about their own systems. Google's FSE'25 paper reports 74% of migration changes LLM-generated and an estimated 50% time saving. Airbnb moved 3.5k test files in 6 weeks. Uber's AutoClean has removed 16k flags and 1M lines. DoorDash got 45 of 50 flags to usable PRs at $4.79 each. Vendors now package this as products: AWS Transform custom, Copilot app modernization, Dependabot alerts assignable to agents, Sourcegraph Agentic Batch Changes, Spotify Fleetshift, Mintlify Autopilot and Claude Code routines. Two points are disputed. First, correctness: benchmarks (FreshBrew) and 2026 papers show reward hacking by deleting tests, silent semantic drift that passes tests, and self-review that approves its own broken output in about a third of cases. Second, net effect: a difference-in-differences study finds AI adoption itself adds lasting tech debt, so "background agents remove entropy" competes with "agents create entropy". Most headline numbers (Amazon's 4,500 developer-years, Nubank's 12x) are vendor or company self-reports with no independent replication.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Hybrid deterministic transform + agent for the judgment calls** | Exact rewrites (AST/codemod/OpenRewrite/Piranha, boolean simplification) are exposed to the agent as tools, often via MCP; the agent handles propagation, call chains, tests and leftover cases the rules miss. This keeps silent behavior changes out of the LLM's hands. | strong | Uber AutoClean, Slack Enzyme->RTL hybrid, OpenRewrite + agent (VirtusLab guide), Codemod (Codemod Agent/Studio/MCP), Spotify Fleetshift, Meta Kotlinator |
| **Discovery-driven migration pipeline (find locations, then LLM edits, then human review)** | Tooling first finds every place that must change (code search, static analysis, flag registry), then sends bounded per-file or per-location LLM tasks in bulk with retry loops tuned on failure buckets. | strong | Google 'Migrating Code At Scale With LLMs', Airbnb Enzyme->RTL, Sourcegraph Agentic Batch Changes, AWS Transform custom |
| **Continuous background cleanup agent from a system of record** | Runs all the time, fed by a source of truth (flag platform, Jira staleness cron, scorecards). It opens review-ready PRs to the owning team and keeps them fresh. The human only decides whether to merge. | strong | Uber AutoClean, DoorDash flag cleanup, GitHub billing team Copilot tech-debt burn-down, Architecture garbage collection (Niessen) |
| **Bot bumps, agent repairs (Renovate/Dependabot + agent on CI failure)** | The rule-based bot opens the version bump. A CI failure triggers a coding agent that pushes a fix commit with a budget/timeout cap and a warning prefix on the PR. Merge-confidence data auto-merges the low-risk bulk. | mixed | arnaudrenaud/fix-with-agent, Dependabot alerts assignable to AI agents, Mend Renovate Enterprise merge confidence, LLM Agents for Automated Dependency Upgrades (JPMorgan), Byam, Fossabot |
| **Scheduled docs-drift agent** | Runs on a cron or on each merge. It reads recent diffs, finds docs or agent instruction files that no longer match the code, and opens draft PRs. | weak | Mintlify Autopilot, Claude Code routines (docs drift example), gh-aw docs-automation gallery |
| **Independent property-checking gate (anti reward hacking)** | The finished diff is checked by things other than the agent that wrote it: a coverage-drop threshold, a patch-coverage minimum, fixers limited to the files they may touch, one reviewer agent per property (no additions, preserves semantics, no intent drift), and edge-case inputs taken from release notes. | strong | Uber AutoClean CodeCourt, DoorDash flag cleanup, FreshBrew, Articulate but Wrong, Accepted but Wrong |
| **Vendor modernization agent for language/framework upgrades** | Packaged agents for Java/.NET/Spring/Python version upgrades and custom org-wide transformations, sold by cloud and IDE vendors. | weak | Amazon Q Developer transformation, AWS Transform custom, GitHub Copilot app modernization, Devin at Nubank |

## Open gaps

- No published success rate for 'Renovate/Dependabot bump + agent fixes CI' in the wild: how often the fix is correct and how often the agent weakens tests.
- No longitudinal data on whether background cleanup agents actually lower debt metrics over months, against the DiD evidence that agent use raises debt.
- Docs-drift agents: no accuracy or false-positive data anywhere, only vendor pages.
- How small teams or solo developers keep up with the review load of continuous maintenance PRs: published numbers come from big companies with owning teams.
- Supply-chain safety of running an agent with tool access on a just-bumped, untrusted dependency (only the hint to use --ignore-scripts was found).
- Independent replication of vendor figures (Amazon 4,500 developer-years, Nubank 12x, Codemod 90% cost reduction, Mend 60-80% auto-merge).
