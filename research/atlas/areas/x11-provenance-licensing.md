# X11. Provenance & licensing

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

By late 2026, recording which code an agent wrote has split into three layers. First, plain-text markers in commits: Co-Authored-By, Assisted-by or Generated-by trailers, bot authors, and session-log URL trailers. Second, line-level recorders such as Git AI (its founders were hired by OpenAI) and the Agent Trace RFC from Cursor, Cognition and others, which store data in git notes or sidecar files. Third, cryptographic layers: signed bot commits, gitsign/Sigstore with workload identity, and SLSA/in-toto attestations. Signed attestations are mostly vendor guidance and young projects, not established practice. The main negative result came from the Linux kernel. Only about 10% of 18,533 commits carried the Assisted-by tag, so the kernel dropped it in October 2026; human Signed-off-by stays, and disclosure moved to the cover letter. Census studies agree: trailer and bot signals capture a fraction of agent activity, and detectors without those signals reach only 0.33 precision. Package hallucination has been measured repeatedly. 2026 frontier models hallucinate 3.6-6% of package mentions, and 53 names shared across vendors could still be registered. The consensus defense is an install-time dependency firewall (Socket sfw, Aikido Safe Chain, GitHub package firewall), not better models. Legal status is mostly settled at the edges and open in the middle. Purely AI output is not copyrightable in the US (Thaler; Copyright Office Part 2), and the Ninth Circuit rejected DMCA 1202 output claims in Doe v. GitHub. Contract claims and the input-side DMCA theory remain open, open-source projects are split from bans (QEMU, Gentoo, NetBSD) to disclosure-only policies, and vendor IP indemnities usually lapse once you edit or combine the output.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Commit-message trailers and bot authorship** | Free-text markers in git history: Co-Authored-By, Assisted-by or Generated-by trailers, agent bot accounts as author with the human as co-author, and URL trailers pointing to session logs. Cheap and searchable, but they prove nothing cryptographically, users can strip them, and compliance is low. | mixed | Linux kernel AI Coding Assistants policy and Assisted-by removal, Claude Code attribution setting and co-author controversy, GitHub Copilot cloud agent signed commits + Agent-Logs-Url trailer, ASF Generative Tooling Guidance, OpenInfra AI policy, Fedora AI-Assisted Contributions Policy |
| **Line-level session recorders (agent hooks + git notes / sidecar)** | Agent hooks checkpoint each edit as AI or human. At commit time an authorship log is attached as a git note or a JSONL sidecar, and it is rewritten across rebase, squash and cherry-pick. This gives line-level AI blame. It cannot cover code written before installation, or edits made outside the hooks. | mixed | Git AI (git-ai-project), Agent Trace spec, coding.sh attribution, agentdiff / Agent Blame / Semantica (via repowise survey) |
| **Cryptographic agent identity and commit signing** | Bind the commit to an identity the agent cannot forge: platform-signed bot commits, gitsign keyless signing with an OIDC or SPIFFE workload identity, and the Rekor transparency log. A signature proves which key or workflow made the commit, not which model wrote the diff. | weak | GitHub Copilot cloud agent signed commits + Agent-Logs-Url trailer, gitsign / Sigstore keyless signing, nucleus SPIFFE agent identity design, Red Hat Rossoctl agent provenance |
| **SLSA / in-toto / AIBOM attestation of agent runs** | Describe the agent run as a build: model, prompt digest, skills, base commit and approver as resolvedDependencies or externalParameters, signed by a runner the agent cannot reach. Optionally add an AI-BOM in CycloneDX or SPDX 3. This is mostly guidance and early implementations, and no standard buildType exists for agent runs. | weak | Safeguard: provenance and AIBOM for agent-made code, Factory: build provenance for coding agent artifacts, hummbl agent-provenance, OpenFab (TODO Group), cdxgen aibom / CycloneDX ML-BOM |
| **Inference and detection from history** | Estimate agent authorship after the fact from bot accounts, trailers, config files and behavioral fingerprints. Useful for research and audits of existing repos. Precision drops sharply once self-disclosed markers are removed. | strong | Detecting AI Coding Agents in Open Source: census of 180M repos, Agent or Human? signature-free commit detection, AgenTag |
| **Install-time dependency firewall against slopsquatting** | A proxy or wrapper around npm, pip, uv or cargo that checks every package, including transitive ones, against a malware feed and a minimum-age cooldown before download. It is applied to agents via a PATH wrapper, a PreToolUse hook, or the platform default. It does not depend on the model getting names right. | mixed | Socket Firewall (sfw), Aikido Safe Chain, GitHub package firewall (public preview), Replit Package Firewall, boda.sh supply-chain security in coding agents |
| **Measuring package hallucination and inference-time mitigation** | Benchmarks of how often models invent package names, how persistent and shared across models those names are, and which decoding, RAG or self-refine defenses reduce the rate. | strong | Spracklen et al. USENIX Security 2025, The Range Shrinks, the Threat Remains (2026 frontier replication), Evaluating Inference-Time Defenses against Package Hallucination (ASE 2026), Lasso huggingface-cli experiment, Setup Complete, Now You Are Compromised |
| **License contamination detection (memorization + snippet scanning)** | Measure how often models reproduce licensed code verbatim, and catch it in CI with snippet-matching scanners or vendor public-code filters. | mixed | LiCoEval, Breaking Copyleft with ChatGPT (2502.05023), FOSSA Snippet Scanning, Black Duck Snippet API, GitHub Copilot public-code matching in agent session logs |
| **Project contribution policies (DCO-centric)** | Open-source projects decide whether AI output can satisfy the DCO or CLA. Positions range from a ban (QEMU, Gentoo, NetBSD), to accepting it with human Signed-off-by plus disclosure (kernel, Fedora, ASF, OpenInfra), to strict disclosure with public denouncement of offenders (Ghostty). | mixed | QEMU code provenance policy, Gentoo/NetBSD bans, Linux kernel AI Coding Assistants policy and Assisted-by removal, ASF Generative Tooling Guidance, OpenInfra AI policy, Fedora AI-Assisted Contributions Policy, Ghostty AI_POLICY, melissawm open-source-ai-contribution-policies list |
| **Legal status and contractual risk transfer** | Copyrightability (human-authorship requirement in the US; UK proposal to drop s9(3)), infringement and DMCA claims over regurgitated code, and vendor IP indemnities with carve-outs for modified or combined output. | strong | US Copyright Office Part 2 + Thaler v. Perlmutter, Doe v. GitHub (9th Cir. 2026), Vendor IP indemnity comparison (Microsoft CCC, OpenAI, Anthropic, Google), UK Report on Copyright and AI (March 2026) |

## Open gaps

- No measured accuracy for session recorders (Git AI, Agent Trace emitters). How often attribution is lost or wrong after real rebase, squash and format workflows is self-reported only.
- No standard SLSA buildType or in-toto predicate for 'agent run produced this diff'. Every vendor invents its own fields, and nobody has published a verifier that blocks merge on it.
- No data on whether disclosure trailers help reviewers or lower defect rates. The kernel shows low compliance, but nobody measured downstream value.
- The bypass rate of install-time firewalls for freshly registered slopsquats (minutes old, before feed flagging) is unmeasured. The trade-off between minimum-age cooldowns and agent productivity is also unmeasured.
- License contamination rates for 2026 frontier agent loops (multi-file, repo-context-heavy) are unknown. LiCoEval and the copyleft studies cover older single-shot models.
- Whether a solo developer owns copyright in largely autonomous agent output, and how employer IP assignment interacts with it, has no case law for code.
- How to reconcile attribution with privacy: session URLs and prompts in commits leak to employer or public repos, and nobody proposes redaction standards beyond Git AI's prompt store.
