# Comprehension tools for decision gates

Read on 2026-11-25. Source list: https://github.com/redikultsev/awesome-codebase-understanding (README, 132 entries, "updated November 2026"). Evidence marks below are the list's: Measured (green), Vendor claim (yellow), Opinion (white), no mark. Tool details come from each tool's own page, fetched the same day. Where a page did not say something, that is stated.

Headline: no tool in the "what did the agent change" section is measured on people. The list says so itself ("None of these tools publishes a measurement on people", https://github.com/redikultsev/awesome-codebase-understanding). Everything in section 1 is design material to borrow, not proven design.

## 2. Measured evidence on how a presentation affects decisions

All taken from the list's "Research on People" section; abstracts re-read at the arXiv pages on 2026-11-25. No study tests a gate card for an agent pipeline. The honest reading: some presentation choices help a little, AI-written summaries often do not improve accuracy, and a wrong summary is costly.

- **Position matters.** "For that type [of seeded defect], participants had 64% lower odds of identifying the defect when its file was shown last rather than first." 106 participants; no effect for the other defect type; human-written code. https://arxiv.org/abs/2208.04259. Implication: put the highest-risk item first.
- **Small changes get reviewed better.** 50 participants: reviews of small changes found significantly more defects; reordering parts showed only a tendency the authors "cannot conclude reliably". https://sback.it/publications/emse2019a.pdf (2019; via the list).
- **A pointer to where to look narrows attention.** 29 professionals: "Reviewers tend to focus on the code locations indicated by the LLM"; more low-severity issues, not more high-severity ones; no time saved; no more confidence. https://arxiv.org/abs/2411.11401. Implication: an AI-flagged "look here" list can hide what it did not flag, so show coverage (what was and was not checked).
- **Wrong description is expensive.** 23,247 agent PRs: 1.7% had high message-code inconsistency; accepted 28.3% vs 80.0%; merge time 55.8 h vs 16.0 h. The commonest inconsistency (45.4%) was a description claiming changes that were never made. https://arxiv.org/abs/2601.04886. Shows a wrong summary costs time; not that a good one saves it (the list's own caveat). Implication: verify claims against the diff and label them by source.
- **Explanations raise confidence, not accuracy.** 86 programmers judged correct generated assertions right 74% of the time and incorrect ones 49%, with the same confidence; explanations gave no overall benefit, poor ones lowered accuracy while raising confidence. https://arxiv.org/abs/2607.08885 (cited via the list; I did not open the abstract). Implication: do not let a confident narrative stand in for evidence; show the evidence the recommendation rests on.
- **AI patches shown to reviewers add time.** Meta randomized trial: reviews over 5% longer when reviewers saw AI-suggested patches; removed when shown only to authors. https://arxiv.org/abs/2507.13499 (via the list).
- **Complexity inflates acceptance of wrong suggestions.** 385 participants: higher complexity significantly increased acceptance of incorrect suggestions; an AI/human label had no supported effect. https://www.zora.uzh.ch/server/api/core/bitstreams/a54a1002-e14e-47f4-b957-2279662becde/content (via the list).
- **Scrutiny decays.** 11,429 reviews by 400 repeat reviewers: approval of agent PRs rose from 30.1% to 36.8%, inline comments fell 22%. https://arxiv.org/abs/2606.22721 (via the list). Implication: a gate that always looks the same invites habituation; surface what changed this time.
- **Asking for focus helps, checklists did not.** 150 participants: asking reviewers to focus on security raised the chance of finding the vulnerability eight times; a security checklist did not improve it further. https://arxiv.org/abs/2202.04586 (via the list). Implication: one explicit question ("decide X; the risk is Y") beats a long checklist.
- **Structured descriptions go with faster response, confounded.** https://arxiv.org/abs/2602.17084; Copilot-written descriptions: reviewed 19.3 h faster, 1.57x likelier to merge, early adopters, merging is not correctness. https://dl.acm.org/doi/10.1145/3643773 (both via the list).
- **What reviewers say they need.** Survey of 180 Microsoft engineers: the rationale of a change was the most important need; risk ("does this change break any code elsewhere?") was very important and among the hardest to get; they asked for caller and impacted-code views. https://yidatao.github.io/paper/tao_fse12.pdf (via the list). Supports putting "why" and "what else is affected" on the card.
- **Visual maps helped in old lab studies, on human code, not change review:** CodeCity +24% correctness and -12% time, 41 participants (https://wettel.github.io/download/Wettel11a-icse.pdf); REACHER call graph 78% vs 14% success on call-flow questions, 12 participants (https://www.computer.org/csdl/proceedings-article/vlhcc/2011/06070388/12OmNxjjEdP); LACY expert-curated tours 83% vs 57% on quizzes, 5 learners (https://arxiv.org/abs/2603.25391). All via the list; small, tool authors' own studies. Closest to our case: structured walkthroughs curated by an expert beat AI-only ones, but n=5.
- **Perception is unreliable.** Experienced developers took 19% longer with AI while believing it made them 20% faster (https://arxiv.org/abs/2507.09089); do not rely on operators saying a view "feels faster". Measure decision time and error rate instead.

## 3. Patterns that repeat

1. **Tiered detail (overview, then file, then snippet).** Trust-Calibrated Code Review (three levels), accountable-review (checkpoint, collapsed supporting evidence, collapsed excerpts), Linear (guide section, then diff), Devin ("Learn more"). Our gate: decision and recommendation, then reasons, then collapsed evidence.
2. **Purpose and risk up front, in plain words.** Sourcery (summary of purpose and risk), Greptile (what, who, why), Linear (risk word), accountable-review ("What changed" first).
3. **Order by importance or by build layer, not by file path.** Linear (core first), CodeRabbit (schema to tests), Devin (grouped by behaviour), accountable-review (reading order of 3-7 stops). Backed by the file-position study.
4. **Hide low-signal material by default.** Linear hides tests and generated files and counts lines without them; Devin shows moves, not delete plus add; difftastic, SemanticDiff drop formatting noise.
5. **File or layer walkthrough table.** PR-Agent file walkthrough, Sourcery file-by-file map, CodeRabbit per-layer summary table.
6. **One diagram, chosen by change type, and none when trivial.** Greptile (sequence, ER, class, flow), accountable-review (max one small figure per checkpoint), Archify (changed nodes marked on a Before/Delta/After diagram).
7. **A coarse verdict plus severity tiers.** Greptile 0-5 with a labelled scale, Linear Low to Very high, Devin red/orange bugs vs Investigate/Informational flags, Entire per-push scores. Caveats: Greptile's own docs say the meaning depends on context; Linear's score is supplied by an outside provider; none publish accuracy.
8. **Say how each claim is known.** accountable-review labels claims as changed code, unchanged code, tests, inference; Archify issues a machine receipt and states it infers no risk; Plannotator calls its findings untrusted evidence; Graphify marks edges extracted, inferred or ambiguous (https://github.com/Graphify-Labs/graphify). The measured wrong-description cost makes this the most defensible pattern.
9. **"How to verify" as its own item.** Sourcery's guide; Simon Willison's "prove it works" (https://simonwillison.net/2025/Dec/18/code-proven-to-work/); Showboat re-runs recorded commands.
10. **Provenance link from change to agent session.** Entire checkpoints, Git AI, Copilot session logs, SpecStory.
11. **Routing: why this reached this person.** CodeRabbit suggested-reviewer rules by path or condition; Linear risk areas; maps to our "why it came to you".
12. **Self-contained HTML as delivery.** Archify and accountable-review both emit one HTML page with inline SVG and light/dark themes; Markdown for chat-sized surfaces (PR-Agent, Greptile).

## Suggested gate-card skeleton (derived, not from a source)

Decision line and options with the recommendation; one-sentence "why it came to you" (the rule that routed it); 3-5 checkpoints each ending in a judgment question; one small figure where it helps (cause chain, change map, before/after, rate sparkline); collapsed evidence per checkpoint with a provenance label; a coverage line (what was checked, what was not); a "how to verify" line. Test it by logging decision time and reversal rate, since no study covers this form.

## Gaps and limits

- docs.pr-agent.ai tool pages returned 404, so PR-Agent's output layout is unconfirmed.
- Sourcery's overview page does not give the guide's layout.
- Linear's and Plannotator's licenses were not stated on the pages read.
- Study numbers marked "via the list" were not re-read at the primary source; those with an arXiv link marked as re-read were.
