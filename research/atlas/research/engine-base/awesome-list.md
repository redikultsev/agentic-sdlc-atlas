## Second look at already-read candidates

The earlier weighting ignored the cost of building the UI. Under the new constraint, these already-read candidates gain, because they already ship a self-hosted web UI and a workflow format with gates:

1. **open-mercato/cezar** (earlier foundation, 2/1/2/2). It has a self-hosted web UI, a v2 YAML node graph with these nodes: agent, check, loop, gate.human, ask-user, fork/join, git, GitHub PR/CI. It also has Jira, GitHub and Linear event automations, a cost dashboard, a phone view, and the MIT licence. Its gaps are the same family as Archon's: no item lifecycle and no real sandbox. It is the closest earlier peer of Archon and should be compared with it head to head.
2. **Fabro** (earlier 2/2/2/2). It has a web UI for gates, JSON routing outputs, Docker or Daytona sandboxes, and per-stage cost. Tracker intake is the gap: the tracker crate is not wired, and Jira is "coming soon". It has the best sandbox and verdict model among engines that have a UI.
3. **Kandev** (2/1/1/2). It has a Go server with an embedded React board, YAML step workflows with event triggers, and executors for Docker, Kubernetes and SSH. The licence is AGPL, which is fine for self-hosted internal use, but a fork would also be AGPL.
4. **Mastra Factory** (2/1/1/2). It has a web board whose state machine moves only along `nextPhases`. It takes intake from GitHub, GitLab, Linear and Jira, runs a sandbox per phase, and has a structured review-verdict tool. It lacks stages 6–9.
5. **Delegatus** (2/1/2/2; earlier marked inspiration_only). It has a web board, a Needs-you queue, verdict routing (pass/fail/needs_decision), a fixed round budget and merge on green checks. It is downgraded mainly because an LLM orchestrator drives the lifecycle. It is worth a recheck only if Archon and cezar both fail.
6. **Sortie** (2/1/1/2). It has an embedded dashboard and the broadest tracker support (GitHub, GitLab, Gitea, Linear, Jira), but by design it never reads agent output. It is a candidate for intake only, not for the orchestrator.
