# Merging agent pull requests

Research of 2026-11-20, three parallel searches: who merges and when without a human, merge queues and stale approvals, the human merge gate for agent PRs. All web access through the fetchira router (serper).

## Answer

1. A merge queue tests the PR on top of the latest main and lands it; when main moves, the queue re-runs the full CI on main + PRs ahead + this PR. Nobody re-runs reviews because main moved: an approval goes stale only when the PR's own diff changes.
2. A conflict or a red queue build ejects the PR; the agent can resolve conflicts (Copilot since Mar 2026), after which the diff changed and checks run again.
3. Merging without a human is allowed only through a mechanical gate: a vetted generator or category, a risk score, path rules, green checks, post-merge monitoring and a kill switch. Free-form agent PRs still get a human or an AI approver everywhere except one OpenAI experimental repo.
4. At the human gate the cheapest useful checks are scope (files outside the plan, dependency changes, size) and the plan; line-by-line reading is eroding into silent approvals. Most reverts of agent PRs come from scope overreach and side effects.

## Merge queues

| System | Re-run when main moved | Approval goes stale when | Failure / conflict | Source |
|---|---|---|---|---|
| GitHub merge queue | Full required checks on main + PRs ahead + this PR | Branch protection: the PR's diff changes; optionally when the merge base brings changes | Ejected, groups behind rebuilt | docs.github.com |
| GitLab merge trains | Full pipeline on the merged result, up to 20 in parallel | Commits added; a rebase that keeps the patch-id keeps approvals | Ejected, pipelines behind restarted; rebase and re-add | docs.gitlab.com |
| Uber SubmitQueue | Speculative builds of future heads; only changes on common build targets conflict | Review before submit | Dependent builds aborted. Main green 52% of the time before; 16 concurrent changes ≈ 40% conflict chance | EuroSys 2019; arXiv 2501.03440 |
| Shopify Shipit | Full CI on a predictive branch, batches of 8 | Checked at `/shipit` | Ejected after 4 consecutive failures (flake tolerance) | shopify.engineering, 2019 |
| Bors, Mergify, Graphite, Aviator, Trunk | Full tests on an integration revision; batching, bisection, stacks | Mostly defer to branch protection (not verified) | Eject, bisect, optimistic merge if a later build passes | vendor docs |

## The human gate on agent PRs

- Merged agent PRs: 79.1% merged with no visible feedback loop; 7.7% had reviewer feedback and agent fixes; 7.7% had a reviewer push commits (missing tests, CI, conventions) (MSR'26, arXiv 2605.22534).
- Claude Code PRs: 83.8% merged vs 91.0% for humans; 54.9% of merged ones unmodified (arXiv 2509.14745).
- One company, 802 developers: PR volume ×3.1, reviewers ×1.5; written feedback fell from 39% to 21% of PRs, silent approvals doubled (arXiv 2607.01904, via Semgrep; not read directly).
- HumanLayer: review the research and the plan, read the tests, stop reading every line. Semgrep: humans only for consequential changes, with targeted questions.
- Conflicts: 27.7% of open or unmerged agent PRs have textual conflicts, rising with size (~10% at 2 lines, ~30% at 25 lines) (arXiv 2604.03551). Copilot resolves conflicts on request since Mar 2026, then builds and tests.
- Changes loop: a human comment makes the agent iterate (Copilot). Only 35.7% of rejected agent PRs were clear agent failures.
- Reverts: 2.66% of agent PRs vs 4.68% of human PRs; causes: overengineering and side effects 22.3%, functional bugs 22.1%, quality 17.7%, dependency upgrades 12.5% (MSR'26, 33,580 PRs).
