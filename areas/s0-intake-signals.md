# S0. Intake & signals

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

By late 2026, getting work to coding agents is a commodity. Every major agent (Copilot cloud agent, Codex, Cursor, Devin, Claude Code, Linear's own agent) takes work from Slack threads, GitHub/Linear/Jira issues, or scheduled and event automations. Monitoring tools (Sentry Seer, Datadog Bits Code) turn telemetry straight into PRs, gated by fixability and impact scores. The open questions have moved upstream:
- deciding what is worth doing (dedupe, clustering, prioritization);
- capturing work agents find along the way without silently widening the current task;
- treating intake as untrusted input.
Practitioners broadly agree on a few patterns: a human-approved label or state machine as the gate before agent execution; confidence-gated triage actions with rationale (GitHub Issues, July 2026); and "report, don't fix" for out-of-scope findings. The most contested point is how much authority triage bots should have. Anthropic's own claude-code dedupe bot drew a public complaint about large-scale false-positive auto-closures. A CERT advisory (Sentry Seer, CVE-2026-90999) and the Cline issue-title injection showed that unauthenticated intake (public DSNs, issue titles) feeding privileged agents leads to code execution. Research on clarification-seeking shows agents can detect underspecified issues. On classic triage tasks such as severity, though, zero-shot LLMs still lose to TF-IDF baselines.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Label-gated work queue with scheduled dispatcher** | A human or triage agent marks issues as agent-ready via a label/state; a cron dispatcher scores, filters (already assigned, open PR, parent issues, exclusion labels), picks independent issues and assigns them to agents with claim labels as mutex and janitors to release stale claims. | mixed | gh-aw Issue Monster (githubnext/agentics), kasbly/issue-pilot, Linear agent platform delegation, /triage skill label state machine (daily.dev write-up) |
| **Chat-thread-as-intake** | Engineer tags an agent in a Slack thread; the whole thread plus linked resources is hydrated as context and the run ends in a PR or a findings reply in-thread. | mixed | Stripe Minions, Cursor 'Fix bugs reported in Slack' automation, Modem feedback-routing guide (Devin/Codex/Claude Tag in Slack) |
| **Telemetry-driven intake with fixability/impact gating** | Errors, flaky tests, perf regressions and vulns become agent tasks automatically, but only above volume/recency/fixability thresholds, with configurable stop points (root cause / plan / draft PR) and impact-based ranking. | weak | Sentry Seer Autofix, Datadog Bits Code, Stripe Minions |
| **Agent-discovered work captured as linked, non-executable tasks** | Agents record findings outside the current scope as new tasks (blocking vs related), deduped against existing ones, created without execution permission; or dedicated scanner agents file issues to refill a queue. | weak | beads (gastownhall/beads), High On Fumes: managing agent-discovered tasks, expatriate/p-backlog, kasbly/issue-pilot, Google Jules Suggested Tasks |
| **LLM triage and dedupe with confidence-gated actions** | Triage agents propose labels, types, assignees, duplicates; high-confidence actions auto-apply, others wait as suggestions with recorded rationale; auto-close after a grace period is the risky variant. | mixed | GitHub Issues agent automation controls, GitHub duplicate detection at issue creation, Linear Triage Intelligence, anthropics/claude-code dedupe and auto-close workflows, Claude Code dedupe bot false-positive complaint (#50898) |
| **Filter-and-verify before handing findings to humans** | Raw AI findings (scanner output, AI bug reports) are deduped, validated and paired with a suggested fix before reaching maintainers, because unverified AI reports are a net cost. | mixed | GitHub/Microsoft Codename MDASH pilot, curl AI slop reports and bug bounty shutdown, OpenAI Aardvark |
| **Clarify-before-execute on underspecified tasks** | A separate intent/underspecification detector decides whether the task is resolvable and asks the requester targeted questions, instead of the coding agent guessing. | strong | Ask or Assume? (uncertainty-aware clarification), Ambig-SWE |
| **Untrusted-intake isolation** | Treat every intake channel (issue text, telemetry events, social mentions) as attacker-controlled; split read-only triage from privileged remediation, deny package installs/egress, and never let triage share caches or credentials with release paths. | strong | Sentry Seer PhantomFix CVE-2026-90999 (CERT VU#212479), Cline issue-triage workflow compromise, Invariant Labs GitHub MCP exploit, Heimdallr (LLM-induced risks in GitHub CI workflows), Empirical study of GitHub Agentic Workflows |

## Open gaps

- No published precision/recall or false-positive rate for any production LLM dedupe or triage bot. Vendors (GitHub, Linear) ship confidence gating without numbers.
- No measurement of the quality, duplicate rate or acceptance rate of issues that agents file themselves (scanners, found-along-the-way findings), or how semantic dedupe works when many parallel agents report the same thing in different words.
- How to prioritize intake for a solo developer whose limit is subscription quota and review attention rather than team capacity. issue-pilot's pacing is the only concrete attempt.
- How to keep intake from employer repos and personal repos separated so cross-repo prompt injection and data leaks (GitHub MCP exploit pattern) cannot happen.
- Whether clarify-before-execute gains hold with real humans who answer late or tersely, rather than oracle simulators.
- When to use deterministic prefilters vs LLM judgment in triage. No head-to-head on real repos beyond severity classification.
