# S10. Operations & incidents

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

By late 2026, "AI SRE" is a crowded, well-funded market. One vendor survey counts 64 tools in 7 camps, Gartner published a market guide, and Resolve AI and Traversal are each valued at $1B or more. The consensus product shape is a read-only investigation agent that triggers on the alert, fans out over telemetry, deploys, code and past incidents, and posts an evidence-linked hypothesis to Slack. Humans approve every production mutation. Independent benchmarks are sobering and contradict vendor claims of 90%+ accuracy: OpenRCA 2.0 finds 20.7% exact root-cause recovery across 11 frontier LLMs, ITBench-AA has every frontier model below 50%, and SREGym shows up to 40% spread across failure types. The main failure mode is verification: agents "declare victory" without checking ground truth, and they produce ungrounded diagnoses. Contested points: build-vs-buy (practitioners report that general coding agents with SRE-written MCPs and skills beat packaged products), whether autonomous remediation is safe at all (Sentry Seer autofix CVE, Kiro/AWS and Replit incidents), and whether AI deskills on-call engineers.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Read-only investigation agent with evidence-linked hypotheses** | Agent auto-triggers on an alert, queries telemetry, deploys, code and incident history in parallel, and posts ranked hypotheses with cited evidence to Slack or the incident tool. No write access by default. | mixed | incident.io Investigations, Cleric, Datadog Bits Investigation, AWS DevOps Agent, Resolve AI, HolmesGPT (new data), Aurora (Arvo AI) |
| **General coding agent + MCP/CLI + team skills as SRE** | Instead of a dedicated product, a standard agent harness (Claude Code, Gemini CLI, Managed Agents) gets read access to clusters, observability MCP servers, runbooks written as skills, and wide CLI tools (az, kubectl). Practitioners report it beats packaged AI SREs at roughly 10x lower cost per run. | mixed | Google SRE Gemini CLI + ProdAgent, Claude Managed Agents SRE cookbook, Azure SRE Agent context-engineering lessons, r/sre AI SRE landscape thread (practitioner reports), abductive-triage skill |
| **Wide tools + code execution + generalist agents over many narrow tools/specialist agents** | Collapse 100+ narrow tools and 50+ specialist agents into a few generalists with broad CLIs. Compute metrics analysis in a code interpreter rather than in context, and page large outputs through files. | weak | Azure SRE Agent context-engineering lessons |
| **Codified deterministic analyzers/playbooks with ML, LLM layered on top** | Engineers write investigation playbooks as code (an SDK plus anomaly detection, time-series correlation and dimension analysis), backtested in code review and auto-run on alerts. A closed set of generic mitigation classes is chosen by an LLM. | strong | Meta DrP, Google SRE Gemini CLI + ProdAgent |
| **Typed mutation tools with risk metadata, policy layer and human approval** | Production changes go only through strictly typed tools tagged safe, reversible or destructive. A policy engine checks context (peak traffic, two-person rule), a human confirms, and everything is audited. Fixes go out as PRs, never as live patches. | mixed | Google SRE Gemini CLI + ProdAgent, Claude Managed Agents SRE cookbook, HolmesGPT (new data) |
| **Backtesting / time-travel evals on historical incidents** | Freeze past incidents with only the context available at alert time and replay new agent versions against them. Grade against what responders actually did, and guard against future leakage (fix PRs, postmortems). | mixed | incident.io Investigations, Meta DrP, AWS DevOps Agent |
| **Adversarial / disconfirming hypothesis loop** | Generate multiple hypotheses in parallel and have a second agent try to disprove each one. Mark findings as validated, invalidated or inconclusive, and let old findings be discounted. | weak | incident.io Investigations, Datadog Bits Investigation, Cleric |
| **Causal / topology-graph RCA** | Maintain a live dependency or causality graph of production (knowledge graph, production context graph) and reason causally over it rather than by correlation over dashboards. | weak | Traversal, Cleric, incident.io Investigations |
| **Fault-injection benchmarks with ground-truth root causes** | Inject faults into live or snapshotted microservice and Kubernetes stacks, then score the agent's root-cause entities, propagation path or mitigation. | strong | OpenRCA 2.0, ITBench-AA, ITBench + MAST failure analysis, SREGym, Grafana o11y-bench |
| **Monitoring-to-coding-agent autofix pipeline** | An error or alert is turned into an RCA and handed to a coding agent that opens a fix PR, sometimes without human review. This is the highest-risk pattern because telemetry is untrusted input. | weak | Sentry Seer Autofix CVE, Datadog Bits Investigation, Meta DrP |
| **Automated postmortem and action-item generation** | Scrape the incident channel, metrics and logs into a timeline, draft the postmortem from a template, and file action items as tracked bugs. | weak | Google SRE Gemini CLI + ProdAgent, incident.io Investigations |

## Open gaps

- No independent, method-disclosed accuracy measurement of commercial AI SREs on real (not injected) incidents; vendor figures of 90%+ conflict with benchmark figures of 20-47%.
- Post-deploy watch is barely documented: how an agent decides that a fresh deploy caused a regression and whether to roll back. Only HolmesGPT's alpha Operator mode and generic canary tooling turned up.
- No published data on auto-remediation success or harm rates in production; every source stops at human-approved PRs or a closed mitigation set.
- How a solo operator or small team gets a backtest set when there are few incidents (Cleric found 12 usable postmortems out of 200+).
- Security model for triage agents that read untrusted telemetry (logs and error reports as a prompt-injection vector) beyond the single Sentry case.
- Cost per investigation for DIY coding-agent setups vs vendors; only anecdotal claims of about 10x cheaper.
- Evidence on deskilling in SRE specifically; the current argument rests on analogies to medicine and aviation.
