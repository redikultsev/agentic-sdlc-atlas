# S8. Integration & merge

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

As of late 2026 the measured facts are these. Agent PRs conflict often: AgenticFlict found 27.67% of about 107K agentic PRs conflict with their base, and in a separate study 41.7% of cross-agent concurrent PR pairs conflicted textually. The best LLMs resolve only about 55-60% of real conflict hunks correctly. Consensus has formed around a few patterns: isolated workspaces (worktrees or jj workspaces), a single integrator (a queue or runner) that tests the combined result, a separate identity for agents with no merge or bypass rights, and approvals pinned to the head SHA (stale approvals dismissed, `gh pr merge --match-head-commit`). Forges have started building for agents. GitHub shipped stacked PRs with a gh-stack agent skill (Jul 2026) and optional Copilot approvals that count toward required reviews (Sep 2026). Cursor launched Origin (Aug 2026). Vendors (Mergify, Trunk, Aviator, Merget, Sheltie, MergeLoop) now sell agent-aware semantic or scoped merge queues. The main dispute is whether merge queues survive agent scale at all. Anthropic's Scion post (Oct 2026, 30K merges a day) says a global merge-queue lock could not be replicated, so it moved to post-merge and pre-deploy testing and lets Claude fix the conflicts that follow. Mergify argues for scoped, batched, speculative queues instead. A string of real incidents (Claude Code, PostHog, Cursor, Hermes) shows that a 'never merge' rule written only in a prompt fails, so the durable control has to live in repository or credential configuration.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Single integrator / merge train over isolated workspaces** | Agents only commit and enqueue. One runner or manager owns the merge-test-push cycle, runs gates on the combined result, and lands the exact tested SHA. | mixed | mergetrain, CAID, Show HN local merge queue (funador), agent-semaphore, Anthropic C compiler agent teams |
| **Agent-aware forge merge queue (batching, scopes, speculative lanes)** | Hosted merge queues that batch and bisect, split a monorepo into scoped lanes, and give agents CLI or skill interfaces such as queue status and flaky-test lookups. | weak | Mergify agent guide, Mergify: Merge Queues Were Built for Humans, Merget, Sheltie, MergeLoop, Trunk/Aviator merge queues, Uber SubmitQueue |
| **Abandon the global merge lock; test post-merge and let agents repair** | At very high merge rates, skip serial pre-merge validation, rely on post-merge and pre-deploy testing with automated bisect and revert, and let agents fix conflicts as they appear. | weak | Anthropic Scion / redesigning source control |
| **Human-only merge authority enforced by configuration, not prompts** | Agents get their own identity with no bypass rights. CODEOWNERS teams and 'approval from someone other than the last pusher' rules apply. Exclusive-mode queues sit on the bypass list. Merge commands and queue-comment buttons are denied at the harness level. | mixed | Mergify agent guide, GitHub Copilot approval rules, PostHog babysit_pr incident, Claude Code auto-merge incident #44202, Cursor fabricated user_query merge, Armor1 exception-label incident |
| **SHA-pinned approvals and merge race guards** | Each approval or test verdict is bound to one head commit. A new push invalidates it, and the merge call refuses if the head moved (`--match-head-commit`, dismiss stale approvals, exact-train identity). | weak | twoperson, gh pr merge --match-head-commit pattern, mergetrain, GitHub Copilot code review approvals |
| **LLM conflict resolution with deterministic validation** | An LLM proposes a resolution. A parser, build, tests or a structural check validates it, and the system retries or abstains. Variants include a neutral third-party reconciler and saved plan-then-apply flows. | mixed | Merge-Bench, Java merge conflicts with calibrated LLM-as-judge, LLM-based vs search-based merge conflict resolution, Hermes merge-reconciler skill, GitKraken gk ai resolve, claude-mergetool / GitNudge / reconcile-ai, LLMs for build conflict resolution (ICST 2026) |
| **Structural / syntax-aware merge** | AST-based merge drivers cut the number of conflicts before an LLM or human sees them. They are deterministic and abstain when unsure. | weak | Mergiraf, GitWand |
| **Stacked changes as the review and merge unit** | Large agent changes are split into dependent small PRs that are reviewed per layer and land together through the queue. | weak | GitHub stacked PRs / gh-stack, Graphite, jj workspaces workflow |
| **Agent-native VCS and forge** | Replace or wrap git: server-side commits and merges, changesets instead of refs, agents working alongside hosted PRs. | weak | Anthropic Scion / redesigning source control, Cursor Origin, jj workspaces workflow |

## Open gaps

- No published measurement of semantic or build-conflict rates (clean textual merge, broken main) for parallel agent PRs. All agent conflict studies are textual-only lower bounds.
- No comparison of how partitioning strategies (worktrees, file leases or ownership maps, stacked PRs, merge queue) change conflict and breakage rates for agents.
- No data on post-merge-repair (Anthropic's approach) versus a pre-merge queue in breakage, revert rate or cost at small scale.
- How to bind test evidence to a SHA without the builder agent attesting it, and how to stop the builder from weakening its own tests.
- Resolving SHA identity versus change identity: avoiding re-reviews after a rebase while keeping approvals pinned.
- No evaluations of the agent-era commercial merge queues (Merget, Sheltie, MergeLoop, Mergify scopes) beyond vendor claims.
- How agents should handle stale red checks and flaky tests in queues without rewriting working code, apart from Mergify's own tooling.
- Cost of running LLM review checks inside merge queues, where each retry re-runs paid reviews.
