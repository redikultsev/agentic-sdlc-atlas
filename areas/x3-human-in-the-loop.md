# X3. Human in the loop

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

As of late 2026, the field has largely moved away from approving every action, and two first-party measurements show why. Anthropic found that users accept 93% of permission prompts and that experienced users auto-approve more but also interrupt more. OpenAI found that a separate reviewer agent cuts human stops about 200x. Both vendors now ship model-based approvers at the sandbox boundary: Claude Code auto mode, which became the default in Aug 2026, and Codex Auto-review. Both use deny-and-continue with a cap on consecutive denials, and humans are moved to monitor-and-interrupt plus a few hard gates on irreversible actions. That consensus is contested in three places. First, independent stress tests find much higher miss rates than vendors report on ambiguous scope (81% FNR on AmPermBench). Second, allow-rules and approvals can themselves be attacked: poisoned repos get agents to propose overly broad allow-rules, and agent PR reviewers can be gamed. Third, HCI and position papers argue that human oversight degrades with use: 20.6% of surveyed developers approve by default, and 61% of careful code reviewers still rubber-stamp actions. Real incidents (Replit, Kiro, PocketOS, DataTalks.Club) consistently point to credentials and scope, not prompts, as the gate that matters. Expanding autonomy "by data" exists mostly as vendor features or practitioner thresholds: per-service auto-merge earned from override and pass rates, and learned per-agent autonomy. I found no rigorous public study validating any such promotion policy.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Model-based approver at the sandbox/permission boundary** | A separate classifier or reviewer agent replaces the human approver for boundary-crossing actions. Safe and in-project actions run without review. Denials return a rationale to the agent (deny-and-continue), and repeated denials escalate to the human or stop the run. | mixed | Claude Code auto mode (Anthropic engineering post), OpenAI Codex Auto-review (alignment post + docs), Measuring the Permission Gate (AmPermBench) |
| **Consequence-aware approval (pre-execute, then approve)** | Run the command in a snapshotted, traced sandbox first and show the approver its observed effects (files, network, secret reads). Commit the result if allowed, roll it back if blocked. This addresses text-only approvers missing what invoked code actually does. | mixed | Caper / Shall We Approve? |
| **Tiered autonomy levels per command risk** | Static risk classes of commands (read-only / workspace modify / remote or irreversible) mapped to user-selected autonomy levels, plus always-on hard blocks. This is the typical CLI agent permission model. | weak | Factory Droid Autonomy Level, OpenAI Codex Auto-review (alignment post + docs), Levels of Autonomy for AI Agents (Feng et al.) |
| **Earned / selective auto-merge by measured trust** | Autonomy is promoted per service, path or agent based on measured pass, override and false-positive rates. High-risk surfaces stay on the human path. A risk assessment decides whether a PR skips human review, and spot checks keep humans calibrated. | weak | Dash0 Six Levels of Agentic SE, Task Machine low-risk auto-merge + learned autonomy, opendatahub-io/auto-merge-agent |
| **Async remote approval (phone push, Slack/chat cards)** | Approval requests leave the terminal as push notifications or chat cards with Approve/Deny buttons, bound to identity and failing closed on timeout. This lets unattended long runs continue. | weak | claude-remote-approver (ntfy), Claude Code Remote Control push, Vercel eve Slack approval cards, LangGraph interrupt + Agent Inbox, OpenAI Agents SDK human-in-the-loop, HumanLayer (pivot and Factory acquisition) |
| **Agent-initiated ask-human / clarification** | The agent detects underspecification or uncertainty and stops to ask, or abstains from acting. Measured as clarification rate versus human interrupt rate, and on benchmarks with underspecified or already-fixed tasks. | mixed | Measuring AI agent autonomy in practice (Anthropic), Ask or Assume?, Coding Agents Don't Know When to Act (FixedBench), MCP elicitation |
| **Blast-radius containment instead of approval (sandbox + scoped credentials, YOLO inside)** | Skip per-action approval and make damage impossible instead: containers or VMs, no production credentials, deletion protection, and a separate human channel for destructive infra changes. | mixed | Simon Willison: Designing agentic loops, Production-deletion incident corpus, HN thread: auto mode default |
| **Overseer-centric design (anti-rubber-stamping)** | Treat human attention as the scarce, degrading resource. Strategic friction, canaries, audits of approval quality, role separation, reversibility indicators, and not treating repeated approvals as stable preferences. | mixed | AI Agents Push Humans Out of the Loop, Let the Agent Do It? (permission decisions study), From Delegation to Action Approval (203-dev survey) |

## Open gaps

- No published, validated policy for promoting autonomy from data. Proposed thresholds (90/5/10 over 20 PRs) are unvalidated, and no one reports promotion outcomes over time.
- No head-to-head independent evaluation of Claude auto mode vs. Codex Auto-review vs. static tier policies on the same workload.
- How to gate effects reached through file edits, as opposed to shell commands, such as editing state files or CI configs. AmPermBench exposes the gap and no deployed fix is described.
- Measured approval quality for async mobile or Slack approvals: do people approve worse on a phone? No data found.
- Operator load for one human supervising many parallel agents: interrupt budget, queueing of approvals, latency cost. No measurements found.
- Neither vendor's incident log is public, and no vendor has published a postmortem for agent-caused data loss.
- How allow-rules accumulate and drift over months in real users' configs. Only anecdotes exist ('python *', 'codex exec --yolo').
