# X9. Tool design for agents

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

By late 2026 the agent-computer interface (ACI) is studied as an engineering field of its own, and the interface often moves results as much as a model upgrade does. Edit-tool format alone moved weak models 5-60 points in Stencil's 2026 hashline benchmark, and Aider showed the same in 2023. Tool descriptions and examples move accuracy 10-20 points (Anthropic, self-report). Three findings have converged across sources. First, accuracy and cost get worse as more tools are loaded, so tools are now loaded on demand: tool search or deferred loading, retrieval (RAG-MCP), toolsets, and "code mode", where the model writes code against a typed API. Second, tool output has to be budgeted with truncation that says it truncated and points the agent to the rest. Third, error text should be actionable, though a 2026 paper shows that where the error is delivered matters too. Practitioners still disagree on three things: bash/CLI-only agents (mini-SWE-agent, Vercel d0) versus typed MCP tools, JSON versus flat CLI arguments, and server-side versus client-side code mode, with Ronacher calling nested code mode harmful. Security is the most unsettled part. The MCP spec keeps moving (the 2026-07-28 revision made the protocol stateless and deprecated Dynamic Client Registration). Tool annotations are officially only untrusted hints. Real incidents (GitHub MCP toxic flow, Supabase, postmark-mcp, mcp-remote RCE) show that a session's risk comes from the combination of tools in it, not from any single server.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Purpose-built ACI commands with guardrails** | Give the agent a small set of agent-specific commands (windowed file viewer, search with capped results, edit with lint-on-save that rejects syntactically broken edits) instead of raw shell or raw APIs. | strong | SWE-agent ACI paper, Anthropic: Writing effective tools for agents |
| **Bash-only / filesystem-as-interface minimalism** | Remove custom tools and give the model one shell tool over a well-documented filesystem; this relies on what frontier models learned in training about Unix tools. | mixed | mini-SWE-agent, Vercel d0: we removed 80% of our agent's tools, Scalekit MCP vs CLI benchmark |
| **Fewer, consolidated, workflow-shaped tools** | Build a few high-level tools that each match a task (e.g. search_logs rather than read_logs, schedule_event rather than list/create), namespace them, and return semantic IDs instead of UUIDs, with a concise/detailed response_format switch. | mixed | Anthropic: Writing effective tools for agents, Microsoft Research: Tool-space interference |
| **On-demand tool discovery (tool search / retrieval / toolsets)** | Do not load every tool schema up front: retrieve a shortlist per query, defer loading, or let users enable toolsets. This shrinks context and improves tool selection, at the cost of a retrieval step that can miss the right tool. | strong | Anthropic advanced tool use (Tool Search Tool), RAG-MCP, How Many Tools Should an LLM Agent See? (Meta), LiveMCPBench, GitHub MCP server toolsets and read-only mode |
| **Code mode / programmatic tool calling** | Expose tools as a typed API that the model calls from code running in a sandbox, so intermediate results stay out of context and calls can be composed in loops. Exists client-side (Anthropic programmatic tool calling, Pi Codemode) and server-side (Cloudflare search()/execute()). | mixed | Cloudflare Code Mode MCP server, Anthropic advanced tool use (Tool Search Tool), Armin Ronacher: What is Codemode |
| **Edit-format engineering** | Choose the edit tool format (str_replace, apply_patch, unified diff, whole file, hash-anchored lines) per model. Format failures can hide most of a model's coding ability. | strong | Stencil: The harness problem (hashline), Aider unified diffs, Diff-XYZ |
| **Output budgeting and truncation with steering** | Cap tool output by tokens rather than lines, keep the head and tail, tell the agent that output was truncated and how to get the rest (pagination, resource links, an overflow file), and prefer structured output. | mixed | Codex tool output truncation issue #6426, Anthropic: Writing effective tools for agents, Pare structured-output MCP servers |
| **Actionable error messages and recovery delivery** | Errors should name the fix (valid values, an example call) and set isError correctly. Where and how the error reaches the model also changes whether it retries, corrects the call or stops. | mixed | Same Error, Different Recovery, Microsoft Research: Tool-space interference, Anthropic: Writing effective tools for agents |
| **Constrained typed inputs over free-form payloads** | Prefer constrained, enumerated flat parameters and input examples over free-form JSON blobs. Shell quoting and nested schemas add failure modes that weaker models cannot recover from. | mixed | Microsoft: Don't rewrite your CLI for agents, Anthropic advanced tool use (Tool Search Tool) |
| **Protocol-level authorization and risk metadata** | An MCP server is an OAuth 2.1 resource server that validates audience-bound tokens, forbids token passthrough and binds client credentials to the issuer. Tool annotations (readOnly/destructive/idempotent/openWorld) are untrusted hints that feed confirmation prompts and policy engines. | mixed | MCP specification 2026-07-28 changelog, MCP authorization security considerations, MCP blog: Tool annotations as risk vocabulary |
| **Session-level toxic-flow / lethal-trifecta defense** | Treat risk as a property of the tool combination in one session (private data + untrusted input + egress) and enforce dataflow rules at runtime (e.g. one repo per session) instead of trusting the model or a single server. | mixed | Invariant Labs: GitHub MCP exploited, Simon Willison: The lethal trifecta, Supabase MCP prompt injection (General Analysis), MCP blog: Tool annotations as risk vocabulary |

## Open gaps

- No independent, multi-task measurement of bash-only vs typed MCP tools vs code mode on the same coding workload with frontier 2026 models; the existing comparisons are vendor-run, cover 5 tasks or are token-only.
- Truncation policy: no study compares head/tail, overflow-file, pagination and summarization strategies for agent task success; the Codex incident is anecdotal.
- Error-message quality: there is ecosystem evidence that errors are bad (MSR) and a recovery-delivery study on open models, but no measurement of 'fix-hint' errors with frontier coding agents.
- Typed mutation tools (dry-run, preview, idempotency keys) versus raw shell for destructive operations: no published measurement of safety and accuracy trade-offs.
- How tool-count degradation scales with 2026 frontier models: most numbers come from 2024-2025 models or vendor-internal evals.
- Whether MCP tool annotations or trust SEPs reduce real incidents: no adoption or effectiveness data beyond '17% use GitHub read-only mode'.
