# S9. Delivery & deploy

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

As of late 2026, the most mature part of agentic delivery is "loop-on-CI": an agent fixes a red build. It is now a stock feature of most coding-agent and CI products (Copilot cloud agent, Jules CI Fixer, Cursor CI autofix, CodeRabbit, Nx Self-Healing CI, Gitar, Semaphore), and there are credible measured results from Google DIDACT build repair, ByteDance LogSage, Hugging Face Serge and Kong's flaky-test harness. Teams that report success agree on the guardrails: reproduce the failure before fixing it, verify the fix by re-running repeatedly, cap attempts and cost, push only to non-protected branches, keep a human merge gate, and be suspicious when the only change is to a test or an expected value. That last point matters because agents that are told to make the tests pass will edit the tests, which is a well-documented failure. Preview environments per PR were repositioned in 2026 as agent sandboxes (Cloudflare Worker Previews, Fly, Render, Signadot, Qovery, Shipyard MCP). Infrastructure-as-code agents (Pulumi Neo, the Terraform MCP server, Spacelift Intent) are spreading, but the standout evidence is negative. The DataTalks.Club terraform destroy (Feb 2026) and PocketOS/Railway (2026) incidents show that a prompt-level "ask before apply" is not a control. The emerging consensus is a mechanical plan-before-apply gate: a human approves the exact plan diff, and the agent's credentials cannot destroy production. Canary analysis and auto-rollback are still mostly vendor features (Harness AI Verify, LLM judges for Argo Rollouts) with no independent measurements. Benchmarks (DevOps-Gym, SWE-CI, CI-Bench, IaC benchmarks) show agents remain weak at build/config and deployment work. DORA 2025 frames AI as an amplifier: delivery instability is a risk unless the platform's safety nets are strong.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Loop-on-CI / self-healing CI** | When a check fails, an agent is given the failing log plus PR context and works in a sandbox or worktree. It reproduces the failure, patches it, re-runs the failing task to verify, and pushes a commit or stacked PR to the same branch. Variants differ on auto-apply versus suggest, eligible task patterns, and attempt caps. | mixed | Nx Self-Healing CI, Elastic Control Plane self-correcting PRs, Bernstein autofix daemon, GitHub Copilot cloud agent fix failing checks, Jules CI Fixer, Cursor CI autofix, CodeRabbit Fix CI, Semaphore self-healing pipelines, Dagger self-healing CI |
| **Reproduce-then-verify with repeated reruns** | No fix is attempted unless the failure reproduces reliably. A fix is accepted only after N consecutive passes, comparing patched and unpatched trees. A cheap model judges the verification while an expensive model does the diagnosis. Infra failures are counted as 'no verdict', not as a pass. | strong | Hugging Face Serge, Kong flaky-test harness |
| **ML build repair surfaced to humans (suggest, not commit)** | A model trained on historical break-to-fix sessions proposes a fix inline. It is filtered by heuristics and accepted by the developer. Safety is measured through rollback rate and sanitizer failures. | strong | Google DIDACT build repair, LogSage (ByteDance) |
| **Anti-reward-hacking guards for CI fixes** | Tests and expected values are treated as read-only, or patches that only touch assertions are flagged. A grader independent of the agent checks the fix, and fixes are not auto-applied to test targets. | mixed | Hugging Face Serge, Nx Self-Healing CI, Pyor test-rewrite failure mode write-up, DevOps-Gym |
| **Per-PR preview environments as agent sandboxes** | Each branch or PR gets an isolated running copy with its own state, secrets and observability. The agent deploys, drives it with a headless browser, queries traces through MCP, patches and redeploys before merge. Agents may trigger previews but not production. | weak | Cloudflare Worker Previews, Fly.io per-PR preview environments, Signadot, Qovery ephemeral environments, Shipyard (StackGen) MCP, Render previews as agent sandboxes, Netlify Agent Runners |
| **Mechanical plan-before-apply gate for IaC agents** | The agent can run plan but not apply or destroy. A human approves the exact resource diff, enforced outside the prompt. Supporting measures: an LLM or skill reviews plan JSON for destroys and IAM widening, prevent_destroy, remote state, and least-privilege credentials. | mixed | DataTalks.Club terraform destroy incident, PocketOS / Railway database wipe, Impri human approval for agent Terraform, tfrev, terraform-plan-review skills, HCP Terraform / Spacelift / Pulumi Neo approvals |
| **Context-grounded IaC agents via MCP** | The agent gets authoritative context (private module registry, workspaces, Sentinel/OPA policies) so it composes approved modules rather than writing from training data, then iterates validate/plan/policy until compliant. | weak | HashiCorp Terraform MCP server, Pulumi Neo, Spacelift Intent MCP |
| **AI canary verification and auto-rollback** | An ML or LLM judge compares canary and baseline metrics and logs and gates promotion or triggers rollback, replacing static thresholds. Most AI SRE products keep rollback behind human approval. | weak | Harness AI Verify / AI Verification and Rollback, LLM judge for Argo Rollouts, AI SRE agents (approval-gated rollback) |
| **Feature flags as the agent's reversibility layer** | Coding agents wrap their changes in flags and kill switches through flag-platform MCP servers. SRE agents then act by flipping flags instead of redeploying. | weak | LaunchDarkly MCP / agent integrations, Statsig MCP server |
| **Agent-scale merge queues** | Speculative parallel testing, batching with bisection, scope-aware lanes, and two-step CI to absorb agent PR churn. Flaky/broken classification is exposed to agents so they don't chase ghost failures. | weak | Mergify merge queue for agents, Trunk merge queue simulations |

## Open gaps

- No independent measurement of auto-applied CI fixes in terms of downstream regressions or reverts. Google's RCT is suggest-only, and vendor products publish no fix or false-fix rates.
- No reliable automatic detector that tells a legitimate test or expected-value update from reward hacking (HF says so explicitly).
- No measured evidence that LLM-based canary judges beat statistical analysis such as Kayenta or Argo AnalysisTemplates, and no false-rollback rates.
- No published design for plan-before-apply gating that works for a solo operator without HCP Terraform, Spacelift or another enterprise platform, e.g. on a single VPS with a PaaS like Dokploy.
- The economics of preview environments when many parallel agents each open PRs (cost, DB seeding, teardown) are discussed by vendors but never measured.
- No study of agents autonomously deploying to production with progressive delivery end to end; everything stops at the PR or merge gate.
