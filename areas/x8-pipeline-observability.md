# X8. Pipeline observability

Phase F1 broad sweep, 2026-11. Not yet verified in depth: `search-snippet` rows were not opened.

## State of the art

As of late 2026, pipeline observability for coding agents follows two patterns. One is native OpenTelemetry export: Claude Code metrics, events and beta traces with W3C TRACEPARENT propagation into subprocesses and the Agent SDK, plus GitHub Copilot's native OTLP. The other rebuilds traces from session transcripts using lifecycle hooks (Stop/SessionEnd) and ships them to Langfuse, LangSmith, Laminar, Braintrust, Phoenix/Arize, Opik or LangWatch. Every major LLM-observability vendor now has a coding-agent plugin. The market has moved from per-trace debugging toward fleet analytics: cost per merged PR (LangSmith outcomes), waste-pattern detection (Datadog Agent Console), LLM classification of recurring failures (Braintrust Topics, Laminar Signals), and a large crop of local-first JSONL archivers (agentsview, codeburn, agentacct). OTel GenAI semantic conventions are the shared vocabulary, with invoke_agent, invoke_workflow, plan and execute_tool spans. But all of it is still at Development stability: the namespace moved to a separate repository with no tagged release, and breaking changes are queued on agent and tool spans. Contested points: hooks capture is telemetry rather than enforcement (developers can turn hooks off), the assembled context (CLAUDE.md, skills) is not captured, cost figures are estimates that diverge from subscription bills, and LLMs are poor at reading traces (TRAIL: the best model scored 11%). Code-provenance standards (Agent Trace, Git AI) add a third axis: which conversation produced each line.

## Approaches

| Approach | What | Evidence | Seen in |
|---|---|---|---|
| **Native OTel export from the agent harness** | The agent emits OTLP metrics, log events and spans itself (sessions, tokens, cost, tool decisions). Content is redacted by default and opened by env flags. W3C trace context goes into subprocesses and API calls, so an orchestrator can parent agent spans under its own trace. | strong | Claude Code monitoring/OTel docs, GitHub Copilot native OTel (via Langfuse guide), claude-code-otel (ColeMurray), Dash0 / OpenObserve / Honeycomb Claude Code guides |
| **Transcript and hook reconstruction** | A Stop or SessionEnd hook reads the local JSONL transcript from a saved offset, rebuilds turns, LLM calls, tool calls and nested subagents, and exports them to a tracing backend. Delivery is best effort. Durations are inferred from timestamps, and assembled context is not captured. | mixed | Laminar Claude Code plugin, Langfuse coding-agent integrations, LangSmith Claude Code plugin, Arize Phoenix coding-harness-tracing, Braintrust coding-agent plugins (bt daemon), Opik Claude Code plugin, disler claude-code-hooks-multi-agent-observability |
| **Standard semantic vocabulary for agent spans** | OTel GenAI semantic conventions define the span types create_agent, invoke_agent (internal and client), invoke_workflow, plan and execute_tool, plus token metrics and opt-in content attributes with external content refs. OpenInference is a parallel vendor convention. | mixed | OTel GenAI agent spans spec, OpenInference (Arize), Particula '0 of 63 stable' critique |
| **Local-first session archive and replay** | Index every agent's on-disk session logs into SQLite or Postgres. Provides full-text and semantic search, per-session cost estimates, HTML replay and team sync, with no SDK and no cloud. | weak | agentsview, claude-replay, simonw claude-code-transcripts, agentlore, codeburn, agentacct, clawmetry, agentglass |
| **Cost attribution to outcomes and tasks** | Link trace spend to PRs, work types, skills, branches or tasks, and report cost per merged PR, unattributed spend, and cost per branch or project. Alternatively, attribute at a gateway through virtual keys or tags. | weak | LangSmith for Coding Agents (outcomes), Datadog Agent Console, LiteLLM tag budgets, Claude Code Analytics API, codeburn, agentacct |
| **Automated trace analysis (LLM reads traces)** | LLM classifiers or scheduled jobs scan traces for recurring failure modes, such as a false success report, a retry loop, an edit outside scope, or context debt, and turn them into findings or fixes to instructions and skills. | weak | Braintrust Coding Agent Insights / Topics / Loop, Laminar Signals (flow-1), Datadog Agent Console Fix Library, Paper Compute, agentsview Friction Log, TRAIL benchmark |
| **Boundary tracing (outside the agent)** | Observe the agent at kernel and network boundaries using eBPF on TLS and process/file syscalls. Needs no SDK, works on closed-source CLIs, and is harder for the agent to evade. | mixed | AgentSight (eunomia-bpf), ThinkWatch gateway |
| **Code provenance and attribution records** | Record which model and conversation produced which lines, keyed to a VCS revision. This links code back to the session trace. | weak | Agent Trace spec (Cursor/Cognition), Git AI (git-notes), agentsview why |

## Open gaps

- No independent measurement comparing native OTel traces against hook-reconstructed traces for the same Claude Code sessions (missing spans, cost drift, duplicates).
- How to attribute cost per task when many parallel agents run on a flat-rate subscription (OAuth) rather than API keys. Vendor analytics APIs reportedly miss these users.
- No validated standard for 'decision' or 'why' spans. The OTel plan span is optional and rarely emitted, and the assembled context (CLAUDE.md, skills, memory) is not captured by any hook-based tool.
- Little evidence that automated trace analysis (Signals, Topics, Friction Log) finds real failures at useful precision. TRAIL shows LLMs at about 11% on trace error localization.
- Tamper-resistant audit logs for agents (written by the agent vs observed externally by eBPF or a gateway). Few real incident postmortems show what logs were actually available.
- Joining three provenance layers end to end: orchestrator task ID, agent session trace, and code lines (Agent Trace or Git AI) through to the merged PR.
